第2章　システム概要

2.1 システム概要

「埼玉鶴瀬・志木スポーツ少年団 統合サイト」（以下、「SKST」という）は、埼玉鶴瀬道院および志木スポーツ少年団に関する情報発信を中心として、イベント写真の管理・公開および少林寺拳法大会情報へのアクセスを一体的に提供するWebサイトシステムである。

SKSTは、WordPress Multisiteを基盤として構築し、1つのWordPress環境内に以下の4サイトを構成する。

埼玉鶴瀬道院

志木スポーツ少年団

イベント写真館

少林寺拳法大会

各サイトはそれぞれ独立した役割を持つ一方、必要に応じてサイト間リンクを設定し、利用者が関連する情報へ移動できる構成とする。

イベント写真館については、一般公開情報に加えて、登録ユーザーのみが閲覧できる写真・イベント情報を管理するため、WordPressアカウントによる認証およびアクセス制御を行う。

少林寺拳法大会サイトについては、既存の「少林寺拳法大会運営プラットフォーム（SKTP）」を利用する。SKSTではSKTPそのものを再設計せず、SKSTを構成する1サイトとして組み込む。

2.2 システムの目的

SKSTの目的は、埼玉鶴瀬道院および志木スポーツ少年団に関する情報を利用者に分かりやすく提供するとともに、活動に関連するイベント、写真および大会情報を適切に管理・公開できる環境を構築することである。

主な目的を以下に示す。

埼玉鶴瀬道院の活動情報を継続的に発信する。

志木スポーツ少年団の活動情報を発信する。

修練日程および年間行事等の情報を分かりやすく提供する。

行事・大会等のイベント情報を管理する。

行事・大会等で撮影した写真をイベント単位で整理・公開する。

必要な写真について、登録ユーザーによる限定公開を可能とする。

YouTube等の外部動画サービスと連携し、活動動画を表示できるようにする。

少林寺拳法大会に関する情報へアクセスできる環境を提供する。

各サイトの役割を維持しながら、関連する情報をサイト間で相互に参照できるようにする。

WordPressの管理機能を活用し、管理者および管理担当者が継続的にサイトを運用できるようにする。

| 2 | 志木スポーツ少年団 | スポーツ少年団の活動情報を発信する | お知らせ、活動情報、イベント等 |
| 3 | イベント写真館 | イベント情報および写真を管理・公開する | イベント情報、写真、ギャラリー、動画等 |
| 4 | 少林寺拳法大会 | 少林寺拳法大会の運営を行う | 大会情報、エントリー、審判、採点、結果等 |

2.3.1 埼玉鶴瀬道院

埼玉鶴瀬道院サイトは、埼玉鶴瀬道院の活動を中心とした情報発信サイトである。

主な情報として、以下を扱う。

お知らせ

修練日程

年間行事

イベント

道院に関する情報

その他の固定ページコンテンツ

イベント写真館に掲載された関連写真については、必要に応じてイベント情報等からリンクして参照できる構成とする。

2.3.2 志木スポーツ少年団

志木スポーツ少年団サイトは、志木スポーツ少年団の活動情報を発信するサイトである。

現在は埼玉鶴瀬道院のイベント情報を利用する部分を持つが、将来的には志木スポーツ少年団が独自にイベントを登録・管理できる構成への拡張を可能とする。

また、埼玉鶴瀬道院サイトおよびイベント写真館へのリンクを設け、関連情報を参照できるようにする。

2.3.3 イベント写真館

イベント写真館は、行事・大会等に関する写真およびイベント情報を管理・公開するサイトである。

イベント情報はカスタム投稿タイプ（CPT）として管理し、写真についてはNextGEN Galleryを利用してギャラリーを構成する。

イベント情報には、必要に応じて写真ギャラリーおよびYouTube等の動画情報を掲載する。

写真等の一部コンテンツについては、登録されたサイト閲覧者のみが閲覧できるようアクセス制御を行う。

また、サイト閲覧者から写真提供を受け付ける機能を設ける。提供された写真は、サイト管理者または管理担当者が確認した後に公開する。

2.3.4 少林寺拳法大会

少林寺拳法大会サイトは、既存の少林寺拳法大会運営プラットフォーム（SKTP）を利用して大会運営を行うサイトである。

SKTPでは、大会情報、拳士エントリー、審判、採点、集計および結果等の大会運営に必要な機能を提供する。

SKSTでは、既存SKTPの機能および設計を変更することを目的とせず、少林寺拳法大会サイトとしてSKSTのサイト構成に含める。

大会に関連する写真については、イベント写真館へのリンクによって参照できる構成とする。

2.5 WordPress Multisite構成

SKSTでは、WordPress Multisiteを採用し、複数のサイトを単一のWordPress環境で管理する。

WordPress Multisiteを採用することにより、以下の構成を実現する。

共通のWordPress基盤によるサイト管理

サイトごとのコンテンツ管理

サイトごとのテーマ・表示構成の管理

WordPressユーザーによる認証管理

サイトごとの権限設定

サイト管理者および管理担当者による運用

各サイトは独立したサイトとしてコンテンツを管理する。

一方で、すべてのサイトで同一のコンテンツを直接共有することを前提とはせず、サイトごとの役割に応じてコンテンツを管理する。

特にイベント情報については、「イベント」と「イベント情報」を区別して管理する。

イベント：Event Organiserで管理するカレンダー上の予定・行事情報

イベント情報：イベントの詳細内容、写真、動画等を掲載するためのコンテンツ

現在、イベントは主として埼玉鶴瀬道院側で管理し、志木スポーツ少年団側から参照する構成とする。ただし、将来的に志木スポーツ少年団が独自のイベントを登録できるよう、拡張可能な構成とする。

2.7 外部サービス・プラグイン

SKSTでは、WordPress標準機能に加え、必要な機能を実現するために外部サービスおよびWordPressプラグインを利用する。

主な外部サービス・プラグインを以下に示す。

| 名称 | 種別 | 主な用途 |
| WordPress | CMS | サイト全体の基盤 |
| WordPress Multisite | WordPress機能 | 複数サイトの統合管理 |
| Event Organiser | プラグイン | イベント・カレンダー管理 |
| NextGEN Gallery | プラグイン | 写真・ギャラリー管理 |
| YouTube | 外部サービス | 動画の公開・表示 |
| メール機能 | WordPress／サーバー機能等 | 登録申請、通知等のメール送信 |

2.7.1 Event Organiser

Event Organiserは、カレンダー上のイベントおよび予定を管理するために利用する。

主として埼玉鶴瀬道院のイベントを管理し、サイト上で修練日程、年間行事等の予定を表示するために利用する。

志木スポーツ少年団については、現在は埼玉鶴瀬道院側で登録されたイベントを利用する構成とするが、将来的な独自イベント登録を妨げない構成とする。

2.7.2 NextGEN Gallery

NextGEN Galleryは、イベント写真館における写真およびギャラリーの管理・表示に利用する。

イベント単位で写真を整理し、イベント情報ページ等から該当する写真を参照できる構成とする。

また、写真へのアクセス制御はイベント情報および利用者の権限に応じて行う。

2.7.3 YouTube

動画については、動画ファイルをSKST内で直接管理するのではなく、YouTube等の外部動画サービスに登録された動画をURL等によって参照する。

イベント情報等から動画を表示できる構成とする。

2.9 システム構成基本方針

本システムは、WordPress Multisiteを基盤として、埼玉鶴瀬道院、志木スポーツ少年団、イベント写真館、少林寺拳法大会の4サイトを構成する。

各サイトは、それぞれの目的および管理対象に応じて独立したサイトとして構成し、サイトごとのコンテンツ管理、ユーザー権限および公開範囲を設定する。

サイト間で関連する情報については、必要な箇所をリンクによって連携するものとし、各サイトのデータを直接共有または同期する方式は採用しない。

イベント写真館については、写真およびギャラリーを管理する独立したサイトとして構成し、認証が必要なコンテンツについては、WordPressのユーザー認証および権限によってアクセスを制御する。

少林寺拳法大会サイトについては、既存のSKTP（大会運営プラットフォーム）を利用するものとし、SKSTではSKTP自体の機能変更や再設計を行わない。少林寺拳法大会サイトからイベント写真館への導線を設けることで、両サイトを利用者の操作上連携させる。

また、既存のイベント写真館については、既存の写真データ、ギャラリーデータおよびイベント情報データを再利用するものとする。

本システムの基本構成を以下に示す。

| 項目 | 基本方針 |

| サイト構成 | WordPress Multisite |

第3章　基本設計方針

3.1 基本設計方針

SKSTの基本設計は、要件定義書で定義した目的、対象範囲および機能要件を基準とし、利用者にとって分かりやすく、管理者にとって継続的に運用しやすいシステムを構築することを基本方針とする。

基本設計においては、以下の方針を基本とする。

WordPress Multisiteを基盤として4サイトを構成する。

各サイトの役割を明確にし、それぞれの目的に応じてコンテンツおよび機能を管理する。

WordPress標準機能を基本とし、必要な機能についてプラグイン等を利用する。

管理者および管理担当者が、専門的なプログラミング知識を必要とせず、継続的にコンテンツを管理できる構成とする。

ユーザー認証にはWordPressのアカウント機能を利用する。

イベント写真館の限定公開コンテンツについては、利用者の認証状態および権限に基づいてアクセスを制御する。

サイト間の情報連携は、原則としてリンクによる参照方式とする。

SKTPとイベント写真館との間では、直接的なデータ同期を行わない。

将来的なコンテンツ追加や志木スポーツ少年団の活動拡大を考慮し、過度な固定化を避けた構成とする。

セキュリティ、保守性および拡張性を考慮した構成とする。

3.2 サイト構成方針

SKSTは、以下の4サイトを1つのWordPress Multisite環境に構成する。

| No. | サイト | 基本的な役割 |
| 1 | 埼玉鶴瀬道院 | 道院の活動および関連情報の発信 |
| 2 | 志木スポーツ少年団 | スポーツ少年団の活動および関連情報の発信 |
| 3 | イベント写真館 | イベント情報および写真の管理・公開 |
| 4 | 少林寺拳法大会 | SKTPによる大会運営 |

各サイトは、それぞれ独立したサイトとして管理する。

サイトごとの役割を明確にすることで、コンテンツの管理場所を明確化し、管理担当者が必要な情報を適切に更新できる構成とする。

また、サイト間で関連する情報については、必要なページから他サイトへリンクすることで、利用者が関連情報を容易に参照できるようにする。

3.2.1 サイトの独立性

各サイトは、基本的に以下の単位でコンテンツを管理する。

投稿

固定ページ

イベント

イベント情報

メディア

写真・ギャラリー

その他、各サイト固有のコンテンツ

ただし、WordPress Multisiteによる統合環境を利用するため、ユーザー認証等の共通基盤を利用できる構成とする。

3.3 コンテンツ管理方針

コンテンツ管理は、WordPressの標準的な投稿・固定ページ機能を基本とし、内容や用途に応じてカテゴリー、タグ、カスタム投稿タイプ等を使用する。

3.3.1 投稿

通常の情報発信にはWordPressの「投稿」を利用する。

主なカテゴリーは以下とする。

| カテゴリー | 用途 |
| お知らせ | 道院・支部等からの告知・案内 |
| 修練日程 | 修練日程に関連する情報 |
| 年間行事 | 年間行事に関連する情報 |

「お知らせ」は、埼玉鶴瀬道院および志木スポーツ少年団のトップページ等に表示する情報として利用する。

投稿に付与するタグによって、埼玉鶴瀬道院および志木スポーツ少年団のどちらに表示するかを判定する。

| タグ設定 | 表示対象 |
| 埼玉鶴瀬道院 | 埼玉鶴瀬道院 |
| 志木スポーツ少年団 | 志木スポーツ少年団 |
| タグなし | 両サイト |
| 両方のタグ | 両サイト |

この方式により、同一の投稿を必要なサイトに表示できる構成とする。

3.3.2 固定ページ

サイトの基本情報や構造上必要となる情報については、WordPressの固定ページを利用する。

固定ページは、サイトの主要なナビゲーションおよび基本情報を構成するコンテンツとして扱う。

画面構成および固定ページの具体的な構成については、第4章「サイト・画面設計」で定義する。

3.3.3 イベント

「イベント」は、Event Organiserによって管理するカレンダー上の予定・行事情報を指す。

イベントは、イベントの日付、時間、開催内容等の予定情報を管理するために使用する。

現在は主として埼玉鶴瀬道院のイベントを管理し、志木スポーツ少年団側から必要な情報を参照する構成とする。

将来的に志木スポーツ少年団が独自のイベントを登録できるよう、サイト構成上の拡張性を確保する。

3.3.4 イベント情報

「イベント情報」は、イベントに関する詳細な情報を掲載するためのコンテンツとして管理する。

イベント情報には、必要に応じて以下の情報を掲載する。

イベントの概要

開催内容

写真ギャラリー

YouTube等の動画

関連情報

関連サイトへのリンク

イベント情報は、WordPressのカスタム投稿タイプ（CPT）として管理する。

なお、「イベント」と「イベント情報」は同一のものとして扱わず、それぞれ異なる目的を持つコンテンツとして管理する。

3.4 ユーザー・権限管理方針

ユーザー管理には、WordPressのユーザー・権限管理機能を利用する。

SKSTでは、利用者の役割に応じて以下の区分を設ける。

| ユーザー区分 | 基本的な役割 |
| サイト管理者 | 対象サイトの管理および運用を行う |
| 管理担当者 | サイト管理者から指定され、担当範囲の管理を行う |
| サイト閲覧者 | 認証後、限定公開コンテンツを閲覧する |
| 閲覧者 | 認証を行わず、一般公開されたコンテンツを閲覧する |

ただし、サイトによって必要なユーザー区分および権限は異なる。

特に、埼玉鶴瀬道院および志木スポーツ少年団では、サイト閲覧者を独立した管理対象として設けず、公開情報を一般の閲覧者が利用する構成を基本とする。

イベント写真館では、限定公開写真等を閲覧するためにサイト閲覧者の認証を必要とする。

少林寺拳法大会サイトについては、既存SKTPのユーザー・権限管理方式に従う。

3.5 アクセス制御方針

アクセス制御は、WordPressのユーザー認証および権限管理を基本とする。

特にイベント写真館では、公開情報と限定公開情報を区別し、限定公開コンテンツについては認証済みユーザーのみが閲覧できる構成とする。

3.5.1 公開コンテンツ

一般の閲覧者がログインせずに閲覧できるコンテンツを公開コンテンツとする。

公開コンテンツについては、通常のWordPressページとして提供する。

3.5.2 限定公開コンテンツ

限定公開が必要な写真・イベント情報については、サイト閲覧者として承認されたWordPressユーザーのみが閲覧できるよう制御する。

未認証の利用者が限定公開コンテンツへアクセスした場合は、ログイン画面を表示する。

認証できない利用者については、対象コンテンツへのアクセスを許可しない。

3.5.3 不正アクセス等への対応

権限を持たない利用者が限定公開コンテンツへアクセスしようとした場合は、アクセスを拒否するとともに、必要に応じてサイト管理者または管理担当者へ通知できる構成とする。

具体的な通知方法およびログ管理については、詳細設計で定義する。

3.6 データ管理方針

データ管理は、各サイトが担当する情報を明確に区分して管理することを基本とする。

3.6.1 データ管理単位

主な管理単位を以下に示す。

| データ | 主な管理対象 |
| 投稿 | お知らせ、修練日程、年間行事等 |
| 固定ページ | サイトの基本情報・構造 |
| イベント | Event Organiserによる予定・行事 |
| イベント情報 | イベントの詳細情報 |
| 写真 | NextGEN Galleryによる写真 |
| ギャラリー | 写真をイベント等の単位で整理したもの |
| 動画情報 | YouTube等へのリンク・埋め込み情報 |
| ユーザー | WordPressアカウント |
| 権限 | ユーザーのサイト・コンテンツへのアクセス権 |

3.6.2 イベントとイベント情報の分離

イベントとイベント情報は、それぞれ異なる管理単位として扱う。

イベントは予定・日程を中心に管理し、イベント情報はイベントの詳細な内容や写真、動画等を掲載するために利用する。

これにより、カレンダー上の予定情報と、開催後の記録・報告情報を分離して管理できる構成とする。

3.6.3 写真データ

写真はイベント写真館で管理し、NextGEN Galleryを利用してギャラリー単位で整理する。

写真の公開については、サイト管理者または管理担当者が確認した上で公開する。

サイト閲覧者から提供された写真については、提供直後に自動公開せず、管理者による確認を経て公開する。

3.7 セキュリティ方針

SKSTでは、WordPressおよびサーバー環境の標準的なセキュリティ機能を適切に利用し、サイトおよび利用者情報を保護する。

基本的なセキュリティ方針を以下に示す。

WordPressを適切に更新する。

使用するプラグインおよびテーマを適切に更新する。

不要なプラグインおよびテーマを導入しない。

管理者権限を必要な利用者に限定する。

管理担当者には必要な範囲の権限のみを付与する。

限定公開コンテンツへのアクセスを認証・権限によって制御する。

アカウント登録時に必要な確認を行う。

一定期間アクセスのないアカウントについて、要件定義書で定めた運用ルールに従って無効化・削除する。

不正なアクセスや権限外の操作を可能な限り防止する。

バックアップを適切に取得し、障害発生時に復旧できる状態を維持する。

セキュリティに関する具体的な設定値、認証方式、ログ管理、バックアップ方式等については、詳細設計および運用設計で定義する。

3.8 保守・拡張方針

SKSTは、継続的にコンテンツを追加・更新することを前提として構築する。

そのため、開発時だけでなく運用開始後の保守および拡張を考慮した設計とする。

3.8.1 保守性

保守性を確保するため、以下を基本とする。

WordPress標準機能を可能な限り活用する。

必要な機能については、適切なプラグインを利用する。

独自プログラムを導入する場合は、役割を明確に分離する。

PHP、CSS、JavaScript等のプログラムを可能な限り適切に分離して管理する。

ソースコードをGitで管理する。

GitHubで変更履歴を管理する。

開発・検証環境で確認した後に本番環境へ反映する。

3.8.2 拡張性

将来的なサイトやコンテンツの拡張を考慮し、特定の運用方法に過度に依存しない構成とする。

特に志木スポーツ少年団については、今後の活動拡大に伴い、現在の運用方法から独立したイベント管理へ移行する可能性があるため、基本設計段階からその可能性を考慮する。

また、イベント情報、写真、動画等についても、今後のコンテンツ増加に対応できる構成とする。

ただし、現時点で要件として定義されていない機能については、必要性が明確になった段階で追加設計を行うものとし、本システムの初期構築範囲に不要な機能を組み込まない。

3.8.3 SKTPとの関係

少林寺拳法大会サイトで利用するSKTPは、独立した既存システムとして扱う。

SKSTの設計・開発では、SKTPの既存仕様を変更せず、必要なサイト間リンクによってイベント写真館との関係を構築する。

SKTP内部の機能、データ構造および処理方式については、SKSTの基本設計では再定義しない。

第4章　サイト・画面設計

4.1 サイト構成

SKSTは、WordPress Multisite上に以下の4サイトを構成する。

| No. | サイト名称 | サイトの役割 |
| 1 | 埼玉鶴瀬道院 | 埼玉鶴瀬道院の活動・行事・修練等の情報を発信する |

サイト間で関連する情報については、必要な画面から他サイトへのリンクを設定する。

イベント情報を掲載するかどうかはイベントごとに異なるため、すべてのイベントに対してイベント情報が存在することを前提としない。

4.7.4 写真・ギャラリー

イベント写真は、イベント単位で整理し、該当するイベント情報から参照できるようにする。

写真の公開範囲は、対象イベント情報の設定および利用者の認証状態・権限に基づいて決定する。

サイト閲覧者から提供された写真は、サイト管理者または管理担当者による確認後に公開する。

4.7.5 アカウント登録申請

イベント写真館では、限定公開コンテンツを閲覧するためのアカウント登録申請を受け付ける。

申請後、サイト管理者または管理担当者が内容を確認し、承認または差戻しを行う。

承認された利用者は、パスワードを設定してログインすることで、権限に応じた限定公開コンテンツを閲覧できる。

4.7.6 写真提供

サイト閲覧者は、写真提供フォームから写真情報を送信できる。

提供された写真は直接公開せず、サイト管理者または管理担当者が内容を確認した後に公開する。

写真提供の基本項目は以下とする。

| 項目 | 内容 |
| 氏名 | 提供者の氏名 |
| メールアドレス | 提供者のメールアドレス |
| イベント名 | 写真の対象となるイベント |
| 画像提供URL | 写真を取得するためのURL |
| メッセージ本文 | 任意のメッセージ |

4.7.7 限定公開コンテンツ

限定公開コンテンツへアクセスする場合は、WordPressアカウントによる認証を必要とする。

認証後、対象コンテンツに対する権限を確認し、閲覧可能な場合のみコンテンツを表示する。

権限がない場合はアクセスを拒否する。

また、権限外のアクセスが発生した場合は、必要に応じてサイト管理者または管理担当者へ通知する。

4.9 共通画面

SKSTでは、複数サイトで共通して利用する画面・機能について、可能な限り統一した考え方で構成する。

4.9.1 ヘッダー

ヘッダーには、サイト名称、主要ナビゲーション等を配置する。

サイト間で関連性がある場合は、必要に応じて他サイトへの導線を設ける。

4.9.2 フッター

フッターには、サイトに関する基本情報、関連サイトへのリンク、必要な案内等を配置する。

4.9.3 ナビゲーション

ナビゲーションは、各サイトの主要コンテンツへ容易にアクセスできる構成とする。

ただし、4サイトすべてで同一のメニュー構成を強制するのではなく、それぞれのサイトの役割に応じたメニューを設定する。

4.9.4 ログイン関連

イベント写真館では、限定公開コンテンツへのアクセスに際してログインを必要とする。

ログイン状態およびユーザー権限はWordPressの認証機能を利用する。

4.10 エラー・認証関連画面

SKSTでは、通常のコンテンツ画面に加えて、認証やアクセス制御、ページ不存在等の状態に対応する画面を設ける。

4.10.1 ログイン画面

登録済みユーザーがWordPressアカウントでログインするための画面である。

主としてイベント写真館の限定公開コンテンツへのアクセス時に利用する。

4.10.2 アクセス拒否画面

認証済みであっても対象コンテンツを閲覧する権限がない場合に表示する。

画面には、対象コンテンツを閲覧できない旨を表示する。

4.10.3 認証エラー画面

ログイン等の認証処理でエラーが発生した場合に表示する。

エラーの詳細情報を不必要に公開せず、利用者が必要な対応を行える内容とする。

4.10.4 404エラー画面

存在しないページや削除されたページへアクセスした場合に表示する。

利用者がサイト内の有効なページへ戻れるよう、トップページ等への導線を設ける。

4.10.5 メンテナンス画面

サイトの保守・更新等により一時的に通常のコンテンツを提供できない場合に表示する。

メンテナンスの実施状況に応じて、利用者へ必要な案内を表示する。

4.11 画面設計方針

本システムの画面は、利用者が必要な情報へ容易に到達できる構成とし、各サイトの目的および利用者区分に応じて画面を構成する。

一般公開画面については、各サイトのトップページを起点として、主要な情報へ階層的に移動できる構成とする。

認証が必要なコンテンツについては、未認証の利用者がアクセスした場合にログイン画面へ誘導し、認証後に許可されたコンテンツを閲覧できる構成とする。

管理画面については、WordPressの管理画面を基本とし、利用者の権限に応じて操作可能な機能を制御する。

また、サイト間で関連する情報については、リンクによる導線を設けるものとし、利用者が現在のサイトから関連するサイトへ容易に移動できるようにする。

画面設計における基本方針を以下に示す。

| 項目 | 基本方針 |
| 一般公開画面 | 各サイトの目的に応じた情報を公開する |
| トップページ | 各サイトの主要情報への入口とする |
| 認証画面 | WordPressユーザー認証を利用する |
| 制限コンテンツ | 認証および権限に応じて閲覧を制御する |
| 管理画面 | WordPress管理画面を基本とする |
| サイト間移動 | 必要に応じてリンクによる導線を設ける |
| エラー画面 | 404、認証エラー、アクセス拒否等を適切に表示する |
| 保守性 | サイト構成および画面構成を明確にする |

詳細な画面項目、画面遷移および画面ごとの処理については、詳細設計書で定義する。

第5章　ユーザー・権限設計

5.1 ユーザー区分

SKSTでは、利用者の役割およびアクセス範囲に応じて、以下のユーザー区分を基本とする。

| ユーザー区分 | 概要 |
| サイト管理者 | 対象サイトの管理・運用を行う利用者 |
| 管理担当者 | サイト管理者から指定され、対象サイトの管理・運用を補助する利用者 |
| サイト閲覧者 | アカウント認証後、限定公開コンテンツを閲覧する利用者 |
| 閲覧者 | ログインせず、一般公開されたコンテンツを閲覧する利用者 |

各ユーザー区分の適用範囲はサイトによって異なる。

5.1.1 サイト管理者

サイト管理者は、対象サイトを管理するための権限を持つ。

主な管理対象は以下とする。

投稿

固定ページ

イベント

メディア

イベント情報

写真・ギャラリー

ユーザー

その他、対象サイトで必要となる管理機能

サイト管理者は、サイトの運用に必要な範囲でコンテンツの登録・編集・削除等を行う。

5.1.2 管理担当者

管理担当者は、サイト管理者から指定された利用者であり、日常的なサイト運用を担当する。

管理担当者には、担当するサイトの運用に必要な権限を付与する。

管理担当者が担当する主な管理対象は以下とする。

投稿

イベント

メディア

イベント情報

写真・ギャラリー

ユーザー

管理担当者には、サイト管理に不要な権限を付与しないことを基本とする。

5.1.3 サイト閲覧者

サイト閲覧者は、登録・承認されたWordPressアカウントを利用して、限定公開コンテンツを閲覧する利用者である。

主としてイベント写真館で利用する。

サイト閲覧者は、管理画面でコンテンツを編集する権限を持たず、対象コンテンツの閲覧を目的とする。

また、イベント写真館では、サイト閲覧者から写真提供を受け付ける機能を設ける。

5.1.4 閲覧者

閲覧者は、ログインせずにWebサイトへアクセスする一般利用者である。

一般公開されているコンテンツについては、閲覧者が自由に閲覧できる構成とする。

限定公開コンテンツについては、認証を行わない閲覧者はアクセスできない。

5.2 サイト別権限

ユーザー区分は、サイトの役割に応じて適用する。

| ユーザー区分 | 埼玉鶴瀬道院 | 志木スポーツ少年団 | イベント写真館 | 少林寺拳法大会 |
| サイト管理者 | ○ | ○ | ○ | SKTP仕様 |
| 管理担当者 | ○ | ○ | ○ | SKTP仕様 |
| サイト閲覧者 | ― | ― | ○ | SKTP仕様 |
| 閲覧者 | ○ | ○ | ○ | SKTP仕様 |

「―」は、当該サイトにおいて独立した管理対象ユーザー区分として設けないことを示す。

少林寺拳法大会サイトについては既存SKTPのユーザー・権限管理方式を利用し、SKSTでは権限体系を再定義しない。

5.3 WordPressユーザー管理

SKSTでは、ユーザー認証およびユーザー管理にWordPressのユーザー機能を利用する。

WordPress Multisite上では、ユーザーアカウントを共通の認証基盤として利用しつつ、サイトごとに必要な権限を設定する。

5.3.1 ユーザーアカウント

ユーザーアカウントは、原則として1利用者につき1アカウントとする。

アカウントには、少なくとも以下の情報を関連付けて管理する。

氏名

メールアドレス

所属情報

アカウント状態

権限情報

登録日時

最終アクセスに関する情報

具体的な管理項目およびデータ保持方式については、詳細設計で定義する。

5.3.2 管理者の登録

サイト管理者および管理担当者については、一般利用者向けのアカウント登録申請とは別に、サイト管理者が必要なユーザーを登録・設定する。

道院・支部サイトの管理担当者について、専用の一般公開登録フォームは設けない。

5.3.3 一般利用者の登録

イベント写真館の限定公開コンテンツを利用する利用者については、サイト上のアカウント登録申請フォームから申請を受け付ける。

申請内容をサイト管理者または管理担当者が確認し、承認された場合にアカウントを利用可能とする。

5.4 アカウント登録申請

イベント写真館では、限定公開コンテンツの閲覧を希望する利用者からアカウント登録申請を受け付ける。

5.4.1 登録申請項目

登録申請フォームでは、以下の項目を入力する。

| 項目 | 必須 | 内容 |
| 姓 | ○ | 氏名の姓 |
| 名 | ○ | 氏名の名 |
| ふりがな（姓） | ○ | ローマ字による姓 |
| ふりがな（名） | ○ | ローマ字による名 |
| メールアドレス | ○ | アカウント連絡先 |
| 期生 | ― | 任意。3～4文字 |
| 道院（支部）名 | ○ | 所属する道院・支部 |
| その他支部名 | 条件付き | 「その他支部」選択時に入力 |
| メッセージ本文 | ― | 任意 |
| CAPTCHA | ○ | 不正な自動送信を防止する |

道院（支部）名の選択肢は以下とする。

埼玉鶴瀬道院

志木スポーツ少年団

和光国際高校

その他支部

「その他支部」を選択した場合は、別途入力されたその他支部名を使用する。

5.4.2 登録申請処理

登録申請時の基本的な処理を以下とする。

登録申請フォーム

↓

入力チェック

↓

申請受付

┌───┴────┐

↓        ↓

申請者通知   管理者通知

↓        ↓

管理者確認

↓

┌────┴────┐

↓         ↓

承認       差戻し

↓         ↓

アカウント利用  差戻理由通知

可能化

登録申請を受け付けた時点では、限定公開コンテンツへのアクセスを許可しない。

管理者による承認処理が完了した後に、利用者がアカウントを使用できる状態とする。

5.4.3 「その他支部」の表示

登録申請時に「その他支部」が選択された場合は、管理者への通知メール等において、選択肢名「その他支部」ではなく、入力された支部名を表示する。

例えば、利用者が「その他支部」を選択し、その他支部名として「○○道院」を入力した場合は、通知内容に「○○道院」を表示する。

5.5 アカウント承認・差戻し

登録申請を受け付けた後、サイト管理者または管理担当者が申請内容を確認する。

5.5.1 承認

申請内容に問題がない場合、管理者は申請を承認する。

承認後、申請者へアカウント利用に必要な案内メールを送信する。

申請者は、案内に従ってパスワードを設定し、ログインする。

承認後の基本的な流れは以下とする。

登録申請

↓

管理者確認

↓

承認

↓

承認通知メール

↓

パスワード設定

↓

ログイン

↓

限定公開コンテンツ閲覧

承認メールの具体的な本文は、要件定義段階では未確定としているため、詳細設計時に確定する。

5.5.2 差戻し

申請内容に確認事項や不備等がある場合、管理者は申請を差戻すことができる。

差戻し時には、差戻理由を記載し、申請者へ通知する。

差戻し理由は管理者が入力する。

5.5.3 再申請

差戻し後に利用者が再度アカウント登録を希望する場合は、登録申請フォームから改めて申請する。

再申請は、新規の登録申請と同じ入力項目および確認手順を利用する。

5.5.4 登録申請メール

登録申請に関するメール通知は、要件定義書で定義した内容に従う。

主な通知は以下とする。

| 通知 | 送信先 | 目的 |
| 登録申請受付 | 申請者 | 登録申請を受け付けたことを通知 |
| 登録申請通知 | サイト管理者等 | 新規申請を通知 |
| 登録申請差戻し | 申請者 | 差戻し理由を通知 |
| 登録承認 | 申請者 | アカウント利用開始を案内 |

登録承認メールの具体的な内容については、要件確定後に定義する。

5.6 アカウント無効化・削除

SKSTでは、長期間利用されていないアカウントについて、一定期間経過後に利用停止および削除を行う。

5.6.1 無アクセス期間24か月

アカウントについて、24か月間ログイン等のアクセスがない場合は、アカウントを無効化する。

無効化されたアカウントでは、限定公開コンテンツへアクセスできない状態とする。

5.6.2 無効化後1年間

アカウントを無効化した後、さらに1年間、利用者からの連絡等がない場合は、アカウントを削除する。

したがって、基本的な管理基準は以下とする。

最終アクセス

│

├── 24か月経過

↓

アカウント無効化

│

├── さらに12か月経過

↓

アカウント削除

具体的な判定方法、管理者への通知、削除前の確認等については、詳細設計および運用設計で定義する。

5.7 アクセス制御

SKSTでは、利用者の認証状態および権限に基づいてアクセス可能なコンテンツを制御する。

5.7.1 基本的なアクセス制御

アクセス制御の基本的な考え方を以下に示す。

| 状態 | 一般公開コンテンツ | 限定公開コンテンツ |
| 未ログイン | 閲覧可 | 閲覧不可 |
| サイト閲覧者 | 閲覧可 | 閲覧可 |
| 管理担当者 | 閲覧可 | 閲覧可 |
| サイト管理者 | 閲覧可 | 閲覧可 |

ただし、実際のアクセス範囲は対象サイトおよびユーザー権限に応じて決定する。

5.7.2 限定公開コンテンツへのアクセス

限定公開コンテンツにアクセスした場合は、まずログイン状態を確認する。

未ログインの場合はログイン画面を表示する。

ログイン後、対象コンテンツを閲覧する権限を確認し、権限を持つ場合のみコンテンツを表示する。

5.7.3 権限外アクセス

認証済みであっても対象コンテンツを閲覧する権限がない場合は、コンテンツを表示しない。

必要に応じてアクセス拒否画面を表示し、サイト管理者または管理担当者へ通知する。

5.7.4 写真へのアクセス

イベント写真館の写真については、イベント情報単位で設定された公開範囲と利用者の権限に基づいてアクセスを制御する。

写真のURLを直接指定してアクセスした場合についても、必要なアクセス制御を適用し、権限のない利用者が限定公開写真を閲覧できない構成とする。

5.8 権限マトリクス

各ユーザー区分の基本的な操作権限を以下に示す。

| 操作 | サイト管理者 | 管理担当者 | サイト閲覧者 | 閲覧者 |
| 公開ページ閲覧 | ○ | ○ | ○ | ○ |
| 限定公開コンテンツ閲覧 | ○ | ○ | ○ | × |
| 投稿閲覧 | ○ | ○ | ○ | 公開範囲による |
| 投稿登録・編集 | ○ | ○ | × | × |
| 投稿削除 | ○ | ○ | × | × |
| 固定ページ管理 | ○ | ○ | × | × |
| イベント管理 | ○ | ○ | × | × |
| イベント情報管理 | ○ | ○ | × | × |
| 写真・ギャラリー管理 | ○ | ○ | × | × |
| 写真提供申請 | ○ | ○ | ○ | ― |
| ユーザー管理 | ○ | ○ | × | × |
| アカウント承認 | ○ | ○ | × | × |
| アカウント差戻し | ○ | ○ | × | × |
| アカウント無効化 | ○ | ○ | × | × |
| アカウント削除 | ○ | ○ | × | × |

「○」は基本的に許可、「×」は許可しないことを示す。

「写真提供申請」は、イベント写真館においてサイト閲覧者が利用する機能であり、管理者・管理担当者についても運用上利用可能とする。

5.9 サイト別ユーザー管理方針

5.9.1 埼玉鶴瀬道院

埼玉鶴瀬道院では、サイト管理者および管理担当者がサイトのコンテンツを管理する。

一般利用者は、原則としてログインせずに公開コンテンツを閲覧する。

イベント写真館の限定公開コンテンツについては、必要に応じてイベント写真館側のアカウント認証を利用する。

5.9.2 志木スポーツ少年団

志木スポーツ少年団では、サイト管理者および管理担当者がサイトを管理する。

一般利用者は、原則としてログインせずに公開コンテンツを閲覧する。

イベント写真館の限定公開コンテンツを閲覧する場合は、イベント写真館側で承認されたアカウントを利用する。

5.9.3 イベント写真館

イベント写真館では、サイト管理者、管理担当者およびサイト閲覧者を管理対象とする。

サイト閲覧者は、登録申請・承認を経てアカウントを取得し、限定公開コンテンツを閲覧する。

サイト管理者および管理担当者は、イベント情報、写真、ギャラリー、ユーザー等の管理を行う。

5.9.4 少林寺拳法大会

少林寺拳法大会では、既存SKTPのユーザー・権限管理方式を利用する。

SKSTではSKTPのユーザー権限を変更せず、SKTP関連設計書に定義された仕様を適用する。

5.10 ユーザー・権限設計の基本方針

本システムでは、WordPressのユーザーアカウントおよび権限管理を基本として、利用者ごとに必要な操作範囲および閲覧範囲を制御する。

ユーザー区分は、サイト管理者、管理担当者、サイト閲覧者および閲覧者を基本とする。

サイト管理者は、対象サイトの管理および運用に必要な権限を有するものとする。

管理担当者は、サイト管理者から指定された範囲において、投稿、イベント、メディア、イベント情報、写真・ギャラリー等の管理を行うものとする。

サイト閲覧者は、アカウントによる認証後、対象となる限定公開コンテンツを閲覧できるものとする。

閲覧者は、ログインを必要としない一般公開コンテンツを閲覧する利用者とする。

ユーザー・権限設計における基本方針を以下に示す。

| 項目 | 基本方針 |
| 認証方式 | WordPressユーザー認証を利用 |
| ユーザー管理 | WordPressユーザー管理を基本とする |
| サイト管理者 | 対象サイトの管理全般を行う |
| 管理担当者 | 指定された管理機能を利用する |
| サイト閲覧者 | 認証後、許可された限定公開コンテンツを閲覧する |
| 閲覧者 | 一般公開コンテンツを閲覧する |
| アカウント申請 | 所定の申請フォームから申請する |
| アカウント承認 | 管理者が申請内容を確認して承認する |
| 差戻し | 必要に応じて差戻し理由を通知する |
| 無効化 | 一定期間アクセスがないアカウントを無効化する |
| 削除 | 無効化後、所定期間連絡がないアカウントを削除する |
| アクセス制御 | サイトおよびコンテンツ単位で必要な制御を行う |

ユーザーごとの詳細な権限およびサイト別の操作範囲については、第5章各節および詳細設計書で定義する。

第6章　コンテンツ・データ設計

6.1 コンテンツ管理方針

SKSTでは、4サイトで取り扱う情報の性質に応じて、WordPress標準の投稿・固定ページ、Event Organiserによるイベント、イベント情報用カスタム投稿タイプ（CPT）、NextGEN Galleryによる写真・ギャラリーを使い分けて管理する。

コンテンツ管理においては、各情報の役割を明確に分離し、同一情報を複数箇所へ重複登録することを避ける。

基本的な管理単位は以下のとおりとする。

| 管理対象 | 主な用途 | 管理方式 |
| 投稿 | お知らせ、修練日程、年間行事 | WordPress標準投稿 |
| 固定ページ | 各サイトの基本ページ、案内ページ等 | WordPress固定ページ |
| イベント | 開催日程・カレンダー情報 | Event Organiser |
| イベント情報 | 行事・大会等の詳細情報 | CPT |
| 写真・ギャラリー | イベントに関連する写真 | NextGEN Gallery |
| 動画 | イベント等の動画 | YouTubeへのリンク・埋め込み |
| ユーザー | アカウント・権限情報 | WordPressユーザー |

コンテンツの登録・編集・公開は、各サイトに設定されたユーザー権限に従って行う。

また、イベント情報、写真、動画等の各コンテンツは、それぞれの管理方式を維持しながら、画面上で相互に参照できる構成とする。

6.2 投稿管理

6.2.1 投稿の用途

WordPress標準の投稿は、主として以下の情報を管理する。

お知らせ

修練日程

年間行事

投稿はカテゴリーによって情報の種類を区分する。

6.2.2 お知らせ

「お知らせ」は、埼玉鶴瀬道院および志木スポーツ少年団に関する告知・案内を管理する。

お知らせは、各サイトのトップページ等に設けるお知らせ表示領域から参照できるものとする。

お知らせからイベント情報やイベント写真館へ誘導する場合は、投稿本文または適切なリンクを使用する。

例えば、イベント写真を公開した場合は、

「少年少女錬成大会の写真を公開しました」

等の案内からイベント写真館へ遷移できる構成とする。

6.2.3 修練日程

「修練日程」は、修練に関する案内を管理する投稿カテゴリーとする。

修練日程カテゴリーの記事は、修練日程ページ内の「修練日程メモ」領域から参照できる構成とする。

6.2.4 年間行事

「年間行事」は、年間の行事に関する案内を管理する投稿カテゴリーとする。

年間行事カテゴリーの記事は、修練日程ページ内の「年間行事」領域から参照できる構成とする。

6.2.5 投稿のサイト別表示

埼玉鶴瀬道院サイトと志木スポーツ少年団サイトでは、投稿タグによって表示対象サイトを制御する。

| タグ | 埼玉鶴瀬道院 | 志木スポーツ少年団 |
| 埼玉鶴瀬道院 | 表示 | 非表示 |
| 志木スポーツ少年団 | 非表示 | 表示 |
| タグなし | 表示 | 表示 |
| 両方のタグ | 表示 | 表示 |

タグによる表示制御は投稿単位で行う。

この仕組みにより、共通して掲載する情報と、特定サイトのみで掲載する情報を同一の投稿管理体系の中で扱う。

6.5 固定ページ

固定ページは、サイトの基本構造を構成するページとして使用する。

固定ページには、サイトの案内、活動紹介、アクセス、各種申請・問い合わせ等、投稿として時系列管理する必要のない情報を配置する。

固定ページの具体的な構成・名称・表示内容は、各サイトの画面設計に従う。

固定ページと投稿は役割を分離し、時系列で追加・更新される情報は原則として投稿で管理する。

また、固定ページからイベント、イベント情報、写真・ギャラリー等の関連コンテンツへリンクすることができる。

6.6 イベント設計

6.6.1 イベントの定義

SKSTにおける「イベント」は、カレンダー上で管理する開催日程を指す。

イベントの管理にはEvent Organiserを使用する。

イベントとイベント情報は同一のものとして扱わず、それぞれ以下の役割を持つものとする。

| 項目 | イベント | イベント情報 |
| 主な役割 | 開催日程の管理 | 行事の詳細情報の管理 |
| 管理方式 | Event Organiser | CPT |
| 主な表示 | カレンダー・日程 | 詳細ページ |
| 写真 | 直接管理しない | NextGEN Galleryへのリンク等 |
| 動画 | 直接管理しない | YouTubeへのリンク・埋め込み等 |

6.6.2 イベント管理主体

現在の運用では、イベント情報は主として埼玉鶴瀬道院が登録・管理する。

志木スポーツ少年団については、現在は埼玉鶴瀬道院側のイベント情報を利用する構成とする。

ただし、将来的に志木スポーツ少年団が独自にイベントを登録・管理できるよう、サイト構成上は独立したイベント管理に対応できるものとする。

6.6.3 イベントの表示

イベントは、サイト上のカレンダーやイベント一覧等から参照できる構成とする。

イベントを選択した場合、必要に応じて関連するイベント情報へ誘導できるものとする。

6.7 イベント情報

6.7.1 イベント情報の定義

「イベント情報」は、行事・大会等について、開催内容や結果、写真、動画等をまとめて掲載するためのカスタム投稿タイプ（CPT）とする。

イベント情報は、Event Organiserで管理する「イベント」とは独立したコンテンツとして管理する。

6.7.2 イベント情報の分類

イベント情報には、以下の分類を設定する。

| 分類 | 内容 |
| 本部行事 | 少林寺拳法本部等に関連する行事 |
| 大会行事 | 大会に関連する行事 |
| 行事 | その他の行事 |
| 少年部 | 少年部に関連する情報 |

「少年部」については、各小学校学年を分類単位として管理する。

6.7.3 イベント情報のタグ

イベント情報には複数のタグを設定できるものとする。

主なタグは以下とする。

埼玉鶴瀬道院

志木スポーツ少年団

各演武会

イベント情報に複数の対象・関連情報を設定する必要がある場合は、複数タグを付与して対応する。

6.7.4 イベント情報と写真

イベント情報ページには、そのイベントに関連する写真・ギャラリーを配置または参照できるものとする。

写真そのものはNextGEN Galleryで管理し、イベント情報CPTが写真データそのものを直接管理する構成にはしない。

6.7.5 イベント情報と動画

イベント情報ページには、必要に応じてYouTubeに公開された動画を参照できるものとする。

動画データそのものはSKSTで保存せず、YouTube上の動画をURLまたは埋め込みによって表示する。

6.8 写真・ギャラリー

6.8.1 写真管理

イベント写真館では、イベントに関連する写真を管理する。

写真・ギャラリーの管理にはNextGEN Galleryを使用する。

写真はイベント単位で整理し、イベント情報から関連する写真・ギャラリーへアクセスできる構成とする。

6.8.2 写真公開

写真は、管理担当者等による確認・公開を経て利用者に表示する。

サイト閲覧者から提供された写真については、提供された時点で自動的に一般公開するのではなく、管理者または管理担当者が確認した上で公開する。

6.8.3 写真のアクセス制御

イベント写真館には、閲覧権限に応じたアクセス制御を設ける。

公開対象に制限が設定された写真・ギャラリーについて、権限を持たない利用者がアクセスした場合は、認証画面等を経てアクセス可否を判定する。

認証できない場合は、対象コンテンツを閲覧できないものとする。

6.8.4 写真削除

公開済みの写真を管理者または管理担当者が削除した場合、その写真へのリンクは提供せず、サイト上では削除された写真が表示されない状態とする。

削除された写真を参照するための公開導線は残さない。

6.9 動画連携

動画はYouTubeに保存し、SKST側では動画そのものを保存・管理しない。

イベント情報ページ等からYouTube動画を参照できるよう、URLまたは埋め込みによって表示する。

動画管理の責任範囲はYouTube側にあり、SKSTでは動画の掲載位置や参照先を管理する。

動画が削除または非公開となった場合の表示状態については、YouTube側の状態に従う。

6.10 サイト間コンテンツ連携

6.10.1 基本方針

4サイト間のコンテンツ連携は、必要な情報へのリンクを基本とする。

サイト間でデータを直接同期する仕組みは設けない。

6.10.2 サイト間の主な関係

| 起点サイト | 遷移先サイト | 主な内容 |
| 埼玉鶴瀬道院 | イベント写真館 | イベント写真の閲覧 |
| 志木スポーツ少年団 | 埼玉鶴瀬道院 | 共通する活動・情報への参照 |
| 志木スポーツ少年団 | イベント写真館 | イベント写真の閲覧 |
| 少林寺拳法大会 | イベント写真館 | 大会関連写真の閲覧 |

イベント写真館は独立したサイトとして運用し、写真・ギャラリー・イベント情報を管理する。

6.10.3 SKTPとの関係

少林寺拳法大会サイトでは既存のSKTPを利用する。

SKSTの基本設計では、SKTPそのものの機能・データ構造を変更しない。

少林寺拳法大会サイトからイベント写真館へ移動する必要がある場合は、リンクによって連携する。

SKTPとイベント写真館との間で、大会情報や写真情報等を直接同期する機能は設けない。

6.10.4 お知らせとイベント情報の関係

「お知らせ」と「イベント情報」は別のコンテンツとして管理する。

お知らせからイベント情報またはイベント写真館へ誘導することはできるが、両者を自動的に同期するものではない。

例えば、

「少年少女錬成大会の写真を公開しました」

というお知らせからイベント写真館へリンクし、遷移先でログイン状態および閲覧権限に応じて写真の閲覧可否を判定する。

6.10.5 データの独立性

各サイトが管理するデータは、それぞれの管理単位を維持する。

特に以下のデータについては、サイト間で直接同期しない。

イベントデータ

イベント情報データ

写真データ

ギャラリーデータ

SKTPの大会運営データ

サイト間で同一の情報を参照させる場合は、必要なページへのリンクを設定する。

第9章　非機能設計

9.1 性能

9.1.1 基本方針

SKSTは、WordPress Multisiteを基盤として4サイトを運用する。

通常のページ閲覧、投稿表示、イベント表示、イベント情報表示等について、利用者が過度な待ち時間を感じることなく利用できる性能を確保する。

特に、イベント写真館では画像を多数表示する可能性があるため、通常のページと写真・ギャラリー表示の特性を分けて考慮する。

9.1.2 性能に関する考慮事項

以下を基本的な性能対策とする。

不要なプラグインを導入しない

不要な処理をページ表示時に実行しない

画像を適切なサイズ・形式で管理する

大量の画像を一度に読み込まない構成を検討する

外部サービスへの依存による表示遅延を考慮する

WordPressおよびプラグインの更新による性能への影響を確認する

9.1.3 写真・ギャラリー

イベント写真館では、通常の文章中心のページと比較して画像データの容量が大きくなる可能性がある。

そのため、写真・ギャラリーについては、NextGEN Galleryの機能を利用しながら、ページ表示に必要以上の画像を同時に読み込まない構成を基本とする。

9.2 可用性

9.2.1 基本方針

SKSTは、埼玉鶴瀬道院、志木スポーツ少年団、イベント写真館、少林寺拳法大会の4サイトを継続的に利用できる状態を維持することを基本とする。

ただし、WordPress、サーバー、ネットワーク、外部サービス等の障害による停止を完全に排除することはできない。

9.2.2 サイト間の独立性

4サイトはWordPress Multisite上で構成するが、各サイトのコンテンツはそれぞれ独立して管理する。

あるサイトのコンテンツ変更が、他サイトのコンテンツを意図せず変更しないようにする。

また、サイト間の情報連携は原則としてリンクによって行うため、サイト間で不要なデータ依存関係を作らない。

9.2.3 外部サービスへの依存

YouTube、Event Organiser、NextGEN Gallery等、外部サービスまたはプラグインに依存する機能については、それらが利用できない場合に対象機能へ影響が生じる可能性がある。

そのため、外部サービスに障害が発生した場合は、SKST本体の障害と切り分けて対応する。

9.3 セキュリティ

9.3.1 基本方針

SKSTでは、WordPressの標準的な認証・権限管理機能を利用し、利用者の権限に応じて管理機能および限定コンテンツへのアクセスを制御する。

特にイベント写真館では、登録ユーザーのみが閲覧できるコンテンツを扱うため、認証・認可を適切に行う。

9.3.2 認証

ユーザー認証にはWordPressのユーザーアカウントを使用する。

限定コンテンツを閲覧する利用者は、必要に応じてログインを行う。

アカウント登録申請は管理者の確認・承認を経て利用可能とする。

9.3.3 権限管理

ユーザーには、サイトおよび利用目的に応じた権限を設定する。

主なユーザー区分は以下とする。

9.3.4 限定コンテンツ

イベント写真館の限定写真・ギャラリー等については、単純にページへのリンクを隠すだけではなく、対象コンテンツへのアクセス時に認証・権限を確認する。

権限のない利用者が限定コンテンツへアクセスした場合は、対象コンテンツを表示しない。

9.3.5 フォームセキュリティ

アカウント登録申請および写真提供申請等のフォームでは、不正な入力や自動送信等を考慮する。

アカウント登録申請ではCAPTCHAを使用する。

入力値については、画面表示・メール送信・データ保存等の処理に応じて適切な入力チェックおよびエスケープを行う。

9.3.6 メールアドレス等の情報

アカウント登録申請では、氏名、メールアドレス、所属等の情報を取り扱う。

これらの情報は、アカウント管理およびサイト運用に必要な範囲で使用し、不必要に公開しない。

9.3.7 更新管理

WordPress本体、テーマ、プラグインについては、セキュリティ更新を含め、適切なタイミングで更新する。

更新時には主要機能への影響を確認し、必要に応じて検証環境で確認した上で本番環境へ反映する。

9.4 バックアップ

9.4.1 基本方針

SKSTでは、障害、誤操作、データ破損等に備えて、WordPressサイトのデータを復旧できるようバックアップを行う。

バックアップ対象には、少なくとも以下を含める。

WordPressデータベース

WordPress本体に保存されたファイル

テーマ

プラグイン

メディア

イベント写真館で管理する必要なデータ

9.4.2 写真データ

イベント写真館では写真データが重要なコンテンツとなるため、通常のサイトデータだけでなく、写真・ギャラリー関連データについても復旧可能な状態を維持する。

9.4.3 バックアップデータ

バックアップデータは、本番環境の障害によって同時に失われることを避けるため、可能な限り本番環境とは分離して保管する。

具体的な保存場所、保存期間、取得頻度等は運用設計で定義する。

9.4.4 復旧確認

バックアップは取得するだけでなく、必要に応じて復元できることを確認する。

本番環境への復旧操作を行う前に、可能な限り検証環境等で復元状態を確認する。

9.5 障害対策

9.5.1 基本方針

障害発生時には、障害箇所と影響範囲を確認し、可能な限り早期に復旧する。

障害については、以下のような区分を基本として考える。

WordPress本体の障害

テーマの障害

プラグインの障害

データベース障害

サーバー障害

ネットワーク障害

外部サービス障害

誤操作・データ削除

9.5.2 障害切り分け

障害発生時には、以下を確認する。

サイト全体が利用できないか

特定のサイトのみ利用できないか

特定のページ・機能のみ利用できないか

特定のプラグインに関連する障害か

外部サービスに関連する障害か

9.5.3 データ障害

データが破損または誤って削除された場合は、バックアップからの復旧を基本とする。

復旧により失われる可能性のある更新内容については、障害発生時点の状況を確認した上で復旧方法を決定する。

9.5.4 プラグイン障害

プラグイン更新後等に障害が発生した場合は、更新内容と障害発生の関係を確認する。

必要に応じて、検証環境で原因を確認してから本番環境を復旧する。

9.6 アクセシビリティ

9.6.1 基本方針

SKSTでは、できる限り幅広い利用者が情報を取得できるよう、アクセシビリティに配慮した画面構成とする。

9.6.2 画面設計

以下を基本的な配慮事項とする。

内容を理解しやすい見出し構造とする

重要な情報を色だけで識別しない

文字を過度に小さくしない

リンク先が分かりやすいリンクテキストを使用する

画像には必要に応じて代替テキストを設定する

フォーム項目を分かりやすく表示する

キーボード操作等を妨げない構成とする

9.6.3 写真・動画

写真については、画像だけに依存せず、必要な場合は説明文等を併記できる構成とする。

動画についても、動画以外の方法で必要な情報を確認できるよう、イベント情報等の文章情報を併せて掲載することを基本とする。

9.6.4 外部サービス

外部サービスやプラグインが提供する表示については、そのサービス・プラグインの仕様に依存する部分がある。

そのため、サイト全体として可能な範囲でアクセシビリティに配慮し、外部機能についても利用可能な範囲で確認する。

9.7 SEO

9.7.1 基本方針

SKSTでは、検索エンジンから必要な情報を適切に発見できるよう、WordPressの基本機能および必要なSEO機能を活用する。

SEOを目的として、利用者にとって不要なコンテンツを増やしたり、検索エンジンだけを対象としたページを作成したりしない。

9.7.2 コンテンツ構造

以下を基本とする。

ページの内容に適したタイトルを設定する

見出し構造を適切に設定する

内容を表すURL構造を検討する

画像に適切な代替テキストを設定する

関連するページ間に適切な内部リンクを設定する

9.7.3 サイト間リンク

4サイト間では、利用者が必要な情報へ移動できるよう、関連性のあるページへのリンクを設定する。

サイト間リンクは利用者の導線を明確にする目的で使用し、検索エンジン向けの不自然なリンク構築は行わない。

9.7.4 限定コンテンツ

イベント写真館の限定コンテンツについては、アクセス制御を優先する。

認証が必要なコンテンツを検索エンジンへ公開することを目的とした構成にはしない。

9.8 保守性

9.8.1 基本方針

SKSTは、将来的なWordPress、テーマ、プラグインの更新および機能追加を考慮し、保守しやすい構成とする。

9.8.2 テーマ・プラグイン構成

独自機能については、テーマとプラグインの役割を適切に分離する。

画面表示に関する処理と、データ管理・機能提供に関する処理を必要に応じて分離し、テーマ変更によって主要機能が失われることを避ける。

9.8.3 標準機能の利用

WordPressの標準機能を可能な限り利用し、同じ機能を独自実装することによる保守負担を抑える。

外部プラグインを利用する場合は、SKSTの要件を満たすために必要なものに限定する。

9.8.4 更新時の確認

WordPress本体、テーマ、プラグインを更新する場合は、以下の主要機能について動作を確認する。

トップページ

投稿表示

イベント表示

イベント情報表示

写真・ギャラリー表示

ユーザーログイン

限定コンテンツへのアクセス

写真提供申請

アカウント登録申請

メール通知

9.9 拡張性

9.9.1 基本方針

SKSTは、現在必要な機能を確実に実現しつつ、将来的なサイト・機能拡張を妨げない構成とする。

ただし、現時点で具体化されていない機能をあらかじめ過度に実装しない。

9.9.2 志木スポーツ少年団の拡張

現在、志木スポーツ少年団では埼玉鶴瀬道院側のイベント情報を利用している。

将来的に活動規模が拡大した場合には、志木スポーツ少年団が独自にイベントを登録・管理できるようにすることを想定する。

9.9.3 イベント情報の拡張

イベント情報CPTは、今後イベントの種類や表示対象が増えた場合にも、カテゴリー・タグ等を利用して整理できる構成とする。

ただし、現時点で必要とされていない分類をあらかじめ追加しない。

9.9.4 写真館の拡張

イベント写真館については、今後、イベント数や写真数が増加することを考慮し、イベント単位で写真・ギャラリーを整理できる構成とする。

9.9.5 大会サイトの拡張

少林寺拳法大会については、SKTPの既存機能を利用する。

SKTP側で将来的な大会運営機能の拡張が行われた場合でも、SKST側ではイベント写真館とのリンク関係を維持できる構成とする。

9.10 非機能設計のまとめ

本システムの非機能設計は、システムを継続的かつ安定して運用できることを基本とし、性能、可用性、セキュリティ、バックアップ、障害対策、アクセシビリティ、SEO、保守性および拡張性について基本方針を定める。

性能については、一般的なWebサイトとして利用者が大きな待ち時間を感じることなく利用できることを目標とする。

可用性については、本番環境において安定したサイト運用を行える構成とする。

セキュリティについては、WordPressおよび使用するプラグイン等を適切に管理し、ユーザー認証、アクセス制御、不正アクセス対策等を行う。

バックアップについては、サイトおよび必要なデータを復旧できるよう、適切なバックアップおよび復旧手段を確保する。

また、アクセシビリティおよびSEOについては、公開サイトとして基本的な配慮を行い、利用者が情報を取得しやすく、検索エンジンからも適切に認識される構成とする。

保守性については、WordPress、テーマ、プラグインおよび独自開発部分を適切に分離・管理し、将来的な修正や更新を行いやすい構成とする。

拡張性については、志木スポーツ少年団の今後の活動拡大等を考慮し、必要に応じて機能やコンテンツを追加できる構成とする。

非機能設計の基本方針を以下に示す。

| 項目 | 基本方針 |
| 性能 | 一般的なWebサイトとして適切な応答性能を確保する |
| 可用性 | 安定したサイト運用を行う |
| セキュリティ | 認証、権限、アクセス制御等を適切に実施する |
| バックアップ | 障害発生時に復旧できるようバックアップを確保する |
| 障害対策 | 障害発生時の確認・復旧手順を整備する |
| アクセシビリティ | 利用者が情報を取得しやすい構成とする |
| SEO | 検索エンジンから適切に認識される構成とする |
| 保守性 | 継続的な更新・修正を行いやすい構成とする |
| 拡張性 | 将来的なコンテンツおよび機能追加に対応できる構成とする |

具体的な設定値、運用条件および実装方法については、詳細設計書および運用設計において定義する。

SKSTは、埼玉鶴瀬道院、志木スポーツ少年団、イベント写真館、少林寺拳法大会の4サイトを継続的に運用する。

基本的な運用方針は以下とする。

WordPressの管理機能を使用してサイトを運用する

利用者の権限に応じて管理できる範囲を制御する

投稿、イベント、イベント情報、写真・ギャラリー等をそれぞれの管理方式に従って運用する

WordPress本体、テーマ、プラグインについて適切に更新する

バックアップを取得し、障害時に復旧できる状態を維持する

10.6 アカウント管理運用

10.6.1 登録申請

イベント写真館を利用するためのアカウントが必要な場合、利用者は登録申請フォームから申請する。

申請を受け付けた後、サイト管理者が申請内容を確認する。

10.6.2 承認

申請内容を確認し、問題がなければアカウントを承認する。

承認後、申請者へメールで通知し、パスワード設定およびログインを行えるようにする。

10.6.3 差戻し

申請内容に確認事項等がある場合は、差戻し理由を記載して申請者へ通知する。

申請者は必要な修正を行い、再度申請する。

10.6.4 アカウント無効化

24か月間アクセスがないアカウントについては、ログインを無効化する。

無効化後、さらに1年間連絡がない場合は、アカウントを削除する。

10.6.5 アカウント情報の管理

ユーザーの氏名、メールアドレス、所属等の情報は、アカウント管理に必要な範囲で利用する。

管理者は、ユーザー情報を適切に管理し、不要な情報を公開しない。

10.7.4 メール送信異常

メールが正常に送信されなかった場合は、申請処理の状況を確認し、必要に応じて管理者が対応する。

10.10 障害発生時の対応

10.10.1 基本方針

障害発生時には、原因および影響範囲を確認し、必要に応じて復旧処理を行う。

障害対応では、原因を確認する前に不要な変更を行わないことを基本とする。

10.10.2 初期確認

障害発生時には、以下を確認する。

どのサイトで障害が発生しているか

すべてのページで発生しているか

特定の機能だけで発生しているか

WordPress本体に関連する障害か

テーマまたはプラグインに関連する障害か

データベースに関連する障害か

サーバーまたはネットワークに関連する障害か

外部サービスに関連する障害か

10.10.3 復旧対応

障害の原因が特定できた場合は、原因に応じて復旧する。

データ破損・誤削除等の場合は、バックアップからの復旧を行う。

プラグインやテーマの更新が原因と考えられる場合は、更新前の状態への復旧等を検討する。

10.10.4 外部サービス障害

YouTube、Event Organiser、NextGEN Gallery等の外部サービス・プラグインに起因する場合は、SKST本体の障害と区別して対応する。

外部サービス側の障害の場合、SKST側で復旧できない場合があるため、影響範囲を確認した上で復旧を待つ等の対応を行う。

SKSTの基本的な運用体制は以下とする。

| 区分 | 主な役割 |
| サイト管理者 | サイト全体の管理、ユーザー管理、コンテンツ管理、公開管理 |

| サイト閲覧者 | 認証が必要なコンテンツの閲覧、写真提供申請 |
| 閲覧者 | 公開されているコンテンツの閲覧 |

サイトによって利用するユーザー区分および権限範囲は異なる。

10.12.2 志木スポーツ少年団

サイト管理者および管理担当者がサイトを管理する。

一般利用者は公開されているコンテンツを閲覧する。

サイト管理者および管理担当者が写真・ギャラリー等を管理する。

サイト閲覧者は、認証された範囲で限定コンテンツを閲覧し、写真提供申請を行うことができる。

10.12.4 少林寺拳法大会

既存SKTPの運用ルールに従って大会運営を行う。

SKSTでは、少林寺拳法大会サイトとイベント写真館との導線を維持する。

10.13 運用上の基本ルール

SKSTの運用では、以下を基本ルールとする。

各コンテンツは適切な管理方式を使用する。

投稿はカテゴリーおよびタグを適切に設定する。

イベントとイベント情報を混同しない。

写真は管理者または管理担当者が確認してから公開する。

限定コンテンツは認証・権限によって保護する。

ユーザーアカウントは必要最小限の権限で管理する。

不要となったアカウントは運用ルールに従って無効化・削除する。

WordPress、テーマ、プラグインは適切に更新する。

更新前に必要なバックアップを取得する。

障害発生時には原因と影響範囲を確認してから復旧作業を行う。

サイト間の情報連携は原則としてリンクで行う。

SKTPの大会運営機能はSKTP側の仕様を維持する。

10.14 運用設計の位置付け

本システムの運用設計は、システムを継続的かつ適切に運用するために必要な基本的な運用方法を定めるものである。

運用については、サイト管理者および管理担当者の役割を明確にし、コンテンツの登録・更新、イベント情報の管理、写真の公開、ユーザーアカウントの管理、メール通知、バックアップ、WordPressおよびプラグインの更新、障害発生時の対応等を行う。

また、サイトごとに管理対象および利用者が異なるため、各サイトの目的および権限に応じた運用を行う。

イベント写真館については、写真提供申請を受け付けた後、管理者または管理担当者が内容を確認し、必要な処理を行った上で公開する運用とする。

ユーザーアカウントについては、登録申請、承認または差戻し、利用状況の確認、無効化および削除までのライフサイクルを管理する。

また、WordPress本体、テーマおよびプラグインについては、サイトの安定性およびセキュリティを考慮し、適切なタイミングで更新を行う。

運用設計の基本的な位置付けを以下に示す。

| 運用項目 | 基本方針 |
| サイト管理 | サイト管理者が全体を管理する |
| コンテンツ管理 | 管理担当者を含め、権限に応じて登録・更新する |
| イベント管理 | Event Organiserを利用して管理する |
| イベント情報管理 | イベント情報CPTを利用して管理する |
| 写真管理 | NextGEN Gallery等を利用して管理する |
| 写真公開 | 管理者または管理担当者が確認後に公開する |
| アカウント管理 | 申請、承認、差戻し、無効化、削除を管理する |
| メール通知 | 所定のタイミングで通知を行う |
| バックアップ | 定期的にバックアップを行う |
| 更新管理 | WordPress、テーマ、プラグイン等を適切に更新する |
| 障害対応 | 障害状況を確認し、必要な復旧対応を行う |

運用に関する具体的な手順、確認項目および対応方法については、詳細設計書ならびに運用手順の中で具体化する。

アカウント登録申請から、承認、利用、無効化、削除までのライフサイクルを管理する。

アカウントは24か月間アクセスがない場合にログインを無効化し、その後1年間連絡がない場合に削除する。

C.7 サイト間連携機能

サイト間連携は原則としてリンクによって行う。

特に以下の導線を提供する。

志木スポーツ少年団 → イベント写真館

少林寺拳法大会 → イベント写真館

SKTPとイベント写真館との間で直接データを同期する機能は設けない。

C.8 少林寺拳法大会機能

少林寺拳法大会サイトでは、既存のSKTPを利用する。

SKTPが提供する大会運営機能については、SKST側で再実装せず、既存機能をそのまま利用する。

SKST側では、必要に応じてイベント写真館へのリンクを提供する。

F.2 WordPress

WordPressをCMSおよびサイト基盤として利用する。

投稿、固定ページ、ユーザー、メディア等の標準機能を利用するとともに、必要な機能についてプラグインを利用する。

F.3 WordPress Multisite

4サイトを1つのWordPress環境で管理するために利用する。

各サイトは独立したサイトとしてコンテンツを管理しながら、同一のWordPress環境内で管理・運用する。

イベントおよびカレンダー情報の管理に利用する。

イベント写真館における写真およびギャラリーの管理に利用する。

F.7 YouTube

動画の保存・公開にはYouTubeを利用する。

少林寺拳法大会サイトでは、既存のSKTPを利用する。

SKSTではSKTPの機能を再構築せず、必要な範囲でサイト間リンクを提供する。

SKTPとイベント写真館との間で直接データを同期する機能は設けない。

F.9 外部サービス利用方針

外部サービスおよびプラグインについては、システム全体への影響を考慮し、以下の方針で利用する。

WordPress標準機能を基本とする。

必要な機能についてプラグインを利用する。

動画はYouTubeを利用する。

写真はNextGEN Galleryで管理する。

イベントはEvent Organiserで管理する。

既存SKTPは大会運営機能として継続利用する。

外部サービスに依存する機能については、外部サービス障害とSKST本体の障害を区別して対応する。

なお、具体的なプラグインのバージョン、設定値、ライセンス、更新手順等は、詳細設計および運用設計で必要に応じて定義する。
