第2章　システム詳細構成

2.1 システム構成

本システムは、WordPress Multisiteを基盤として構築し、複数のサイトを同一のWordPress環境上で管理する。

本システムを構成するサイトは、以下の4サイトとする。

埼玉鶴瀬道院

志木スポーツ少年団

イベント写真館

少林寺拳法大会

各サイトは、それぞれの目的に応じたコンテンツおよび機能を提供する。

基本的なシステム構成は以下のとおりとする。

| 構成要素 | 内容 |
| CMS | WordPress |
| サイト構成 | WordPress Multisite |
| サイト数 | 4サイト |
| サイト管理 | WordPress管理画面 |
| コンテンツ管理 | WordPress標準機能およびプラグイン |
| カレンダー | Event Organiser |
| 写真・ギャラリー | NextGEN Gallery |
| 動画 | YouTube |

| バージョン管理 | Git / GitHub |

システム全体では、WordPress本体、テーマ、プラグインおよび各サイトのコンテンツを組み合わせて機能を実現する。

2.2 WordPress Multisite構成

本システムでは、WordPress Multisiteを利用して複数サイトを構築する。

Multisiteを利用することにより、WordPress本体を共通基盤として利用しながら、各サイトについて独立したサイト管理領域およびコンテンツを管理する。

各サイトは同一のWordPress Multisite環境に属するが、サイトごとに必要なページ、投稿、イベント、イベント情報、写真等を管理する。

また、ユーザーアカウントについてはWordPressのユーザー管理機能を利用する。

2.2.1 Multisiteの基本構成

| 項目 | 内容 |
| WordPress | 共通基盤として利用 |
| Multisite | 複数サイトを管理 |
| サイト | 4サイト |
| ユーザー | WordPressユーザーとして管理 |
| 権限 | WordPressの権限・ロールを利用 |
| テーマ | サイト構成に応じて適用 |
| プラグイン | 必要なサイトで利用 |
| データ管理 | WordPress標準のサイト単位管理を基本とする |

各サイトで利用するテーマおよびプラグインは、サイトの機能要件に応じて設定する。

大会運営については、SKTP（大会運営プラットフォーム）を利用する。

SKTP自体の機能およびデータ構造については、SKTPの関連設計書で定義するため、本システムの詳細設計では、主として以下を対象とする。

イベント写真館へのサイト間連携

少林寺拳法大会サイトとイベント写真館との間では、直接的なデータ連携は行わない。

必要な情報については、各サイトのページ、投稿またはイベント情報等からリンクすることにより連携する。

2.4 テーマ・プラグイン構成

本システムでは、WordPressのテーマおよびプラグインを利用して各サイトの機能を構成する。

2.4.1 テーマ

テーマは、サイトのデザインおよび画面表示を制御する。

各サイトについて必要な表示内容を実現するため、共通化できる部分とサイト固有の部分を整理して構成する。

テーマの詳細なテンプレート構成、CSS、JavaScriptおよび各サイト固有の表示処理については、第3章以降で定義する。

2.4.2 プラグイン

主要なプラグイン構成を以下に示す。

| プラグイン・機能 | 主な用途 |
| Event Organiser | イベントおよびカレンダー管理 |
| NextGEN Gallery | 写真・ギャラリー管理 |
| フォーム機能 | アカウント登録、写真提供等のフォーム |
| SKTP | 少林寺拳法大会の大会運営 |

2.9 詳細構成の基本方針

本システムの詳細構成について、以下を基本方針とする。

2.9.1 WordPress Multisiteを基盤とする

複数サイトを個別のWordPressとして構築するのではなく、WordPress Multisiteを利用して一元的に管理する。

2.9.2 サイトごとの独立性を確保する

各サイトは、それぞれの目的および利用者に応じたコンテンツを管理できる構成とする。

必要に応じてサイト間をリンクするが、サイト間で不要なデータ共有を行わない。

2.9.3 共通機能は可能な限り共通化する

ユーザー管理、認証、基本的なWordPress機能等については、WordPress Multisiteの共通基盤を利用する。

一方、サイト固有の機能については、それぞれのサイトの要件に応じて構成する。

2.9.4 写真・イベント情報を分離して管理する

カレンダー上の「イベント」と、詳細情報を掲載する「イベント情報」は別の機能・データとして管理する。

また、写真・ギャラリーについてもイベント情報と関連付けて表示するが、イベントカレンダーそのものと同一のデータとして扱わない。

2.9.5 SKTPとは必要な範囲で連携する

少林寺拳法大会サイトではSKTPを利用するが、SKTPの大会運営データとイベント写真館のデータを直接統合しない。

大会終了後の写真公開等については、必要なページへのリンクによって連携する。

2.9.6 開発環境と本番環境を分離する

開発・検証はローカル環境で行い、十分な確認を行った後に本番環境へ反映する。

ソースコードについてはGitおよびGitHubによって管理し、変更履歴を保持する。

2.9.7 将来の拡張を考慮する

志木スポーツ少年団の活動拡大等により、現在共有している機能を将来的に独立して管理する必要が生じる可能性を考慮する。

特にイベント管理については、現在の運用だけに限定せず、志木スポーツ少年団が独自にイベントを登録・管理できる構成を維持する。

3.1 ユーザー区分

本システムでは、利用者を以下の区分に分類する。

| ユーザー区分 | 概要 | 認証 |
| サイト管理者 | 本システムおよび各サイトの管理を行う利用者 | 必要 |

なお、サイト閲覧者については、サイト管理上の独立した管理権限を付与するものではなく、必要なコンテンツを閲覧するための認証済み利用者として扱う。

ユーザーの権限については、ユーザーが所属するサイトおよび担当範囲に応じて設定する。

3.9 ログイン・ログアウト

3.9.1 ログイン

WordPressの認証機能を利用してログインする。

ログイン時には、登録された認証情報を確認し、認証に成功した場合はログイン状態とする。

ログイン後は、ユーザーに設定された権限に応じて利用可能なコンテンツを表示する。

保護されたコンテンツに未認証状態でアクセスした場合は、ログインを要求する。

3.9.2 ログアウト

ログイン中のユーザーがログアウト操作を行った場合、WordPressのログイン状態を終了する。

ログアウト後は、認証を必要とするコンテンツを閲覧できない状態とする。

3.10 パスワード設定・変更

承認されたアカウントについて、初回ログイン前にパスワードを設定する。

パスワード設定は、WordPressが提供するパスワード設定機能を利用する。

ログイン後のパスワード変更についても、WordPressのアカウント管理機能を利用する。

パスワードを忘れた場合は、WordPressのパスワード再設定機能を利用する。

パスワードそのものは本システム側で平文保存しない。

3.11 アカウント無効化

ユーザーが長期間ログインしていない場合、アカウントを無効化する。

ログインが24か月（2年間）確認できないアカウントを、ログインできない状態に変更する。

無効化されたアカウントは、保護されたコンテンツを閲覧できない。

無効化後に利用を再開する必要がある場合の取り扱いについては、サイト管理者が確認の上、必要な対応を行う。

3.12 アカウント削除

アカウントを無効化した後、さらに1年間連絡がない場合は、対象アカウントを削除する。

したがって、最後のログインから24か月経過して無効化されたアカウントについて、その後1年間連絡がない場合は削除対象とする。

アカウント削除を行う際には、対象ユーザーを確認した上でサイト管理者が実施する。

削除されたアカウントではログインできず、保護されたコンテンツを閲覧できない。

アカウントの状態と基本的な取り扱いを以下に示す。

| 状態 | 内容 | ログイン |
| 申請中 | 登録申請を受け付け、承認待ちの状態 | 不可 |
| 承認済み・利用可能 | サイト管理者による承認が完了し、利用可能な状態 | 可 |
| 差戻し | 申請内容の確認結果として差戻された状態 | 不可 |
| 無効 | 24か月ログインがなく、利用停止となった状態 | 不可 |
| 削除 | 無効化後1年間連絡がなく、アカウントを削除した状態 | 不可 |

差戻し後は、同一申請を復旧するのではなく、登録申請フォームから再申請する。

また、アカウントのライフサイクル管理は、サイト管理者がユーザーの利用状況を確認しながら適切に実施する。

第4章　画面詳細設計

4.1 画面設計方針

本システムの画面は、WordPress Multisiteを構成する各サイトの役割および利用者区分に基づいて設計する。

画面設計においては、以下を基本方針とする。

4.1.1 サイトごとの役割を明確にする

各サイトは、それぞれ以下の役割を持つ。

埼玉鶴瀬道院：道院の活動、修練、行事等の情報を提供する。

志木スポーツ少年団：スポーツ少年団の活動、修練、行事等の情報を提供する。

イベント写真館：イベント情報、写真およびギャラリーを提供する。

少林寺拳法大会：大会情報およびSKTPによる大会運営機能を提供する。

4.1.2 公開範囲を明確にする

画面およびコンテンツは、一般公開、認証済み利用者向け、管理者向けに区分する。

特にイベント写真館では、公開対象となる写真と限定公開される写真を区別し、限定公開コンテンツについてはログイン状態および利用者権限を確認する。

4.1.3 イベントとイベント情報を分離する

「イベント」はカレンダー上の予定を管理する機能であり、「イベント情報」はイベントの詳細内容を掲載する情報として扱う。

両者は同一の画面・データとして扱わず、必要に応じてリンクによって遷移する。

4.1.4 サイト間の連携はリンクを基本とする

サイト間の情報連携は、原則としてページ、投稿、イベント情報等から対象サイトのページへリンクする方式とする。

サイト間で不要なデータの直接共有は行わない。

4.1.5 WordPress標準機能との整合性を確保する

投稿、固定ページ、ユーザー、メディア等については、WordPress標準の画面構成および操作方法を基本とする。

プラグインによって提供される画面については、それぞれのプラグインの機能に従って構成する。

4.2 画面ID体系

本システムでは、画面を識別するために画面IDを付与する。

画面IDは、以下の体系とする。

| 識別子 | 対象 |
| C | 共通画面 |
| T | 埼玉鶴瀬道院サイト |
| S | 志木スポーツ少年団サイト |
| P | イベント写真館 |
| K | 少林寺拳法大会サイト |
| M | 管理画面 |

画面IDは、識別子と連番を組み合わせて付与する。

例：

C001：共通画面

T001：埼玉鶴瀬道院サイト

S001：志木スポーツ少年団サイト

P001：イベント写真館

K001：少林寺拳法大会サイト

M001：管理画面

同一画面について、表示内容や遷移先が異なる場合は、必要に応じて個別の画面IDを付与する。

画面IDは、画面仕様、画面遷移、テスト仕様および実装時の管理単位として使用する。

第5章　機能詳細設計

5.1 機能設計方針

本システムの機能は、基本設計書で定義した業務要件およびサイト構成に基づいて実装する。

機能設計においては、以下を基本方針とする。

5.1.1 WordPress標準機能を基本とする

投稿、固定ページ、ユーザー、メディア等については、WordPressが提供する標準機能を基本として利用する。

必要な機能については、プラグインまたはテーマによる拡張を行う。

5.1.2 イベントとイベント情報を分離する

「イベント」はカレンダー上の予定を管理する機能とし、「イベント情報」はイベントの詳細内容を管理する機能とする。

両者は別々に管理し、必要な場合にリンクによって関連付ける。

5.1.3 写真とイベント情報を連携する

イベント情報から、該当する写真・ギャラリーを表示できる構成とする。

写真の実体およびギャラリーの管理はNextGEN Galleryを利用する。

5.1.4 写真の公開には確認を必要とする

サイト利用者から提供された写真は、申請を受け付けただけでは公開しない。

サイト管理者または管理担当者が内容を確認した上で公開する。

5.1.5 閲覧制御を行う

イベント写真館の限定公開コンテンツについては、ユーザーの認証状態および設定されたタグ等に基づいて閲覧可否を判定する。

5.1.6 サイト間連携はリンクを基本とする

サイト間でデータを直接共有するのではなく、原則としてページ、投稿、イベント情報等から対象ページへリンクする。

5.2 投稿管理機能

投稿管理機能は、WordPressの投稿機能を利用して、各サイトで掲載する記事を管理する。

投稿にはカテゴリーおよびタグを設定する。

主な投稿カテゴリーは以下とする。

お知らせ

修練日程

年間行事

また、表示対象サイトを指定するため、サイト識別タグを利用する。

投稿の基本的な管理操作は以下とする。

新規登録

編集

公開

更新

非公開

削除

カテゴリー設定

タグ設定

投稿の表示対象サイトは、設定されたタグによって判定する。

5.3 お知らせ管理機能

お知らせ管理機能は、WordPressの投稿機能および「お知らせ」カテゴリーを利用して実現する。

お知らせは、埼玉鶴瀬道院および志木スポーツ少年団のサイトで表示する。

表示対象は、投稿に設定されたサイト識別タグによって制御する。

5.4 修練日程管理機能

修練日程管理機能は、WordPressの投稿機能および「修練日程」カテゴリーを利用して管理する。

修練日程に関する投稿は、修練日程ページの「修練日程メモ」に表示する。

表示対象サイトは、投稿に設定されたサイト識別タグによって制御する。

埼玉鶴瀬道院と志木スポーツ少年団の双方に表示する場合は、タグを設定しない、または両サイトのタグを設定する。

5.5 年間行事管理機能

年間行事管理機能は、WordPressの投稿機能および「年間行事」カテゴリーを利用して管理する。

年間行事に関する投稿は、年間行事ページの「年間行事」欄に表示する。

表示対象サイトは、投稿に設定されたサイト識別タグによって制御する。

投稿の登録・編集・公開等は、サイト管理者または対象サイトの管理担当者が行う。

5.6 イベント管理機能

イベント管理機能は、Event Organiserを利用して実現する。

イベントは、カレンダー上の予定として管理する。

イベント情報CPTとは別の機能として管理し、必要な場合にイベント情報へのリンクを設定する。

5.6.1 イベント登録

管理担当者またはサイト管理者は、イベント管理画面からイベントを登録する。

イベント登録時には、Event Organiserで定義されるイベント情報を入力する。

登録したイベントは、対象サイトのイベント画面に表示する。

現在の基本運用では、埼玉鶴瀬道院を中心としてイベントを登録する。

将来的に志木スポーツ少年団の活動が増加した場合には、志木スポーツ少年団独自のイベントを登録できる構成とする。

5.6.2 イベント編集

登録済みのイベントについて、管理担当者またはサイト管理者が内容を編集できる。

編集した内容は、イベントを表示する画面に反映する。

イベント情報CPTの内容は、イベントを編集しただけでは自動的に変更しない。

5.6.3 イベント削除

不要となったイベントは、管理担当者またはサイト管理者が削除する。

削除後は、対象イベントをカレンダー等に表示しない。

イベント情報CPTおよび関連写真については、イベント削除によって自動削除しない。

これは、イベントとイベント情報・写真を別の管理対象として扱うためである。

5.6.4 イベント表示

登録されたイベントは、対象サイトのイベント画面に表示する。

イベント表示では、カレンダーとして利用者が開催日等を確認できる構成とする。

イベントの詳細情報が別途登録されている場合は、イベント情報へのリンクを設定できる。

5.6.5 サイト別イベント表示

イベントは、対象となるサイトに応じて表示する。

埼玉鶴瀬道院のイベントと志木スポーツ少年団のイベントを区別して管理できる構成とする。

現行運用では、志木スポーツ少年団が埼玉鶴瀬道院のイベント情報を利用する場合があるが、将来的な独立運用を妨げない構成とする。

5.7 イベント情報管理機能

イベント情報管理機能は、WordPressのカスタム投稿タイプ（CPT）を利用して実現する。

イベント情報は、イベントの詳細内容を掲載するための情報であり、Event Organiserで管理する「イベント」とは別のデータとして管理する。

5.7.1 イベント情報登録

管理担当者またはサイト管理者は、イベント情報管理画面からイベント情報を登録する。

イベント情報には、イベント名称、開催内容、写真、動画、関連情報等を必要に応じて登録する。

登録したイベント情報は、イベント情報一覧および詳細画面に表示する。

5.7.2 イベント情報編集

登録済みのイベント情報を編集する。

編集可能な内容には、本文、分類、タグ、写真、動画および関連情報等を含む。

編集後、公開中のイベント情報に変更内容を反映する。

5.7.3 イベント情報削除

不要となったイベント情報は、管理担当者またはサイト管理者が削除する。

イベント情報を削除しても、関連するイベントカレンダーのデータおよび写真データを自動的に削除しない。

必要なデータについては、それぞれの管理機能から個別に管理する。

5.7.4 カテゴリー設定

イベント情報には、以下の分類を設定する。

本部行事

大会行事

行事

また、少年部については学年別の分類を利用する。

分類はイベント情報の整理および一覧表示等に利用する。

5.7.5 タグ設定

イベント情報には、表示対象および関連対象を識別するためのタグを設定する。

主なタグは以下とする。

埼玉鶴瀬道院

各演武会

複数のタグを設定できるものとする。

タグが設定されていないイベント情報については、基本的に埼玉鶴瀬道院を対象とする。

タグに基づく閲覧制御が必要な場合は、設定されたタグをアクセス制御の判定情報として利用する。

5.7.6 写真連携

イベント情報には、関連する写真・ギャラリーを表示できる。

写真の管理はNextGEN Galleryで行い、イベント情報から該当するギャラリーへ遷移または表示する。

写真はイベント単位で整理することを基本とする。

イベント情報の本文に写真を直接掲載する場合と、ギャラリーとして表示する場合を必要に応じて使い分ける。

5.7.7 動画連携

イベント情報には、YouTubeで公開された動画を表示またはリンクできる。

動画ファイル自体をWordPress内に保存するのではなく、YouTube上の動画を利用する。

動画の公開状態および削除等については、YouTube側の状態に従う。

5.8 写真・ギャラリー管理機能

写真・ギャラリー管理機能は、NextGEN Galleryを利用して実現する。

イベントごとに写真を整理し、イベント情報から関連するギャラリーを表示できる構成とする。

5.8.1 ギャラリー作成

管理担当者またはサイト管理者は、イベント単位等でギャラリーを作成する。

ギャラリーには、対象イベントが識別できる名称を設定する。

作成したギャラリーは、イベント情報等から表示できるように設定する。

5.8.2 写真登録

写真はNextGEN Galleryに登録する。

登録時には、対象イベントのギャラリーに写真を追加する。

写真提供申請によって提供された写真については、確認・承認が完了するまでは公開対象として扱わない。

5.8.3 写真公開

登録された写真を公開する場合は、管理担当者またはサイト管理者が公開対象として設定する。

公開対象となった写真は、設定された公開範囲に従ってイベント情報およびギャラリーから閲覧できる。

限定公開対象の場合は、認証済み利用者に対してのみ表示する。

5.8.4 写真編集

管理担当者またはサイト管理者は、登録済み写真について必要な編集を行う。

編集対象には、写真情報、ギャラリーへの所属、公開状態等を含む。

公開済みの写真についても、必要に応じて内容を変更できる。

5.8.5 写真削除

不要となった写真は、管理担当者またはサイト管理者が削除する。

写真を削除した場合、対象写真は以後のギャラリー表示に反映されない。

削除した写真について、別途「未反映」等の状態を管理する機能は設けない。

5.8.6 写真閲覧制御

写真の公開範囲を設定し、一般公開写真と限定公開写真を区別する。

一般公開写真は、認証なしで閲覧できる。

限定公開写真は、WordPressアカウントによるログインが必要であり、さらに設定された閲覧条件を満たす利用者のみ閲覧できる。

未ログイン状態で限定公開写真へアクセスした場合は、ログイン画面へ遷移する。

5.8.7 タグによる閲覧制御

限定公開コンテンツの閲覧制御には、イベント情報等に設定されたタグを利用する。

基本的な対象タグは以下とする。

埼玉鶴瀬道院

志木スポーツ少年団

各演武会

タグによって対象を識別し、利用者が閲覧条件を満たしているかを確認する。

閲覧条件を満たさない利用者が対象コンテンツへアクセスした場合は、アクセス拒否として処理する。

5.9 写真提供申請機能

写真提供申請機能は、利用者からイベント写真の提供を受け付けるための機能である。

提供者から直接画像ファイルをシステムへ公開するのではなく、画像を保存したURLを受け付ける。

5.9.1 申請受付

写真提供申請フォームから以下の情報を受け付ける。

氏名

メールアドレス

イベント名

画像提供URL

メッセージ本文

必須項目について入力チェックを行い、正常な場合に申請を受け付ける。

申請受付時点では、写真を公開しない。

5.9.2 URL受付

画像提供URLを入力項目として受け付ける。

入力欄には、画像保存先のURLを入力する旨を表示する。

URLは提供された写真を確認するために利用し、申請を受け付けた時点で自動的に公開コンテンツへ登録しない。

5.9.3 管理者通知

写真提供申請を受け付けた場合、サイト管理者へメール通知を送信する。

5.9.4 提供写真の確認

サイト管理者または管理担当者は、申請された画像提供URLを確認する。

確認対象には、以下を含む。

提供された画像がイベントに関連しているか

公開に適さない内容が含まれていないか

ギャラリーへ登録可能な内容であるか

確認の結果、公開可能と判断した場合に、管理者または管理担当者が写真を登録する。

5.9.5 公開処理

確認済みの写真をNextGEN Galleryへ登録し、必要なイベント情報およびギャラリーへ反映する。

公開範囲については、対象イベントの設定に従う。

限定公開対象の場合は、認証およびタグによる閲覧制御を適用する。

申請された写真を公開しない場合は、ギャラリー等へ登録しない。

アカウント登録申請

アカウント差戻し

再申請

ユーザー情報管理

権限設定

ログイン・ログアウト

パスワード設定・変更

アカウント無効化

アカウント削除

アカウント登録申請については、申請者からの登録を直接有効化せず、サイト管理者による確認および承認を経て利用可能とする。

アカウントのライフサイクルについては、第3章の仕様に従う。

5.11 アクセス制御機能

アクセス制御機能は、利用者の認証状態、ユーザー権限およびコンテンツの公開条件に基づいて、閲覧可能なコンテンツを制御する。

基本的な判定を以下とする。

| 状態 | 一般公開 | 限定公開 |
| 未ログイン | 閲覧可 | 閲覧不可 |
| ログイン済み・閲覧条件を満たす | 閲覧可 | 閲覧可 |
| ログイン済み・閲覧条件を満たさない | 閲覧可 | 閲覧不可 |

限定公開コンテンツへ未ログイン状態でアクセスした場合は、ログイン画面へ遷移する。

ログイン後に必要な閲覧条件を満たしていない場合は、アクセス拒否画面を表示する。

また、管理画面については、WordPressユーザーの権限に基づいて利用可能な機能を制御する。

サイト間連携機能は、各サイトから関連する別サイトの情報へ遷移するための機能である。

第6章　コンテンツ詳細設計

6.1 コンテンツ設計方針

本システムで管理するコンテンツは、WordPress標準機能を利用して管理するコンテンツと、カスタム投稿タイプ（CPT）を利用して管理するコンテンツに分類する。

コンテンツの種類および用途を以下に示す。

| コンテンツ | 管理方式 | 主な用途 |
| 投稿 | WordPress標準投稿 | お知らせ、修練日程、年間行事 |
| 固定ページ | WordPress標準固定ページ | サイトの基本ページ、案内ページ |
| イベント | Event Organiser | カレンダー形式の予定管理 |
| イベント情報 | CPT | イベントの詳細情報 |
| 写真・ギャラリー | WordPressメディア・NextGEN Gallery | イベント写真の管理・公開 |
| 動画 | YouTube | イベント等の動画公開 |

コンテンツ設計においては、以下を基本方針とする。

コンテンツの用途に応じて管理方式を分離する。

「イベント」と「イベント情報」は別のコンテンツとして管理する。

投稿カテゴリーにより、投稿の用途を分類する。

投稿タグおよびイベント情報タグにより、対象サイトを指定する。

イベント情報には、行事種別と少年部の分類を分けて設定する。

写真はイベント単位でギャラリーを構成する。

動画はYouTube上で管理し、イベント情報から参照する。

コンテンツ間の関連付けは、必要に応じてリンクにより行う。

コンテンツの公開状態と閲覧権限を区別して管理する。

サイト別表示制御は、各コンテンツに設定されたタグを基準として行う。

6.2 投稿

投稿は、埼玉鶴瀬道院サイトおよび志木スポーツ少年団サイトで使用する一般的な記事コンテンツである。

投稿はWordPress標準の投稿機能を利用して登録・編集・公開する。

投稿には、本文、タイトル、公開状態、カテゴリー、タグ等を設定する。

6.2.1 投稿の用途

投稿は以下の用途に使用する。

| 用途 | カテゴリー | 表示内容 |
| お知らせ | お知らせ | 道院・支部からのお知らせ |
| 修練日程 | 修練日程 | 修練日程に関する情報 |
| 年間行事 | 年間行事 | 年間行事に関する情報 |

「お知らせ」は、埼玉鶴瀬道院サイトおよび志木スポーツ少年団サイトのトップページに設けるお知らせ表示領域で使用する。

「修練日程」は、修練日程ページの「修練日程メモ」で使用する。

「年間行事」は、修練日程ページの「年間行事」欄で使用する。

6.2.2 投稿の基本項目

| 項目 | 内容 |
| タイトル | 投稿のタイトル |
| 本文 | 投稿本文 |
| カテゴリー | 投稿の用途を分類 |
| タグ | 表示対象サイトを指定 |
| アイキャッチ画像 | 必要に応じて設定 |
| 公開状態 | 下書き、公開等 |
| 公開日時 | 公開日時 |

投稿は、カテゴリーとタグの組み合わせにより、用途および表示対象サイトを決定する。

6.3 投稿カテゴリー

投稿カテゴリーは、投稿の用途を分類するために使用する。

本システムで使用する投稿カテゴリーを以下に示す。

| カテゴリー | 用途 | 主な表示場所 |
| お知らせ | 道院・支部からのお知らせ | 各サイトトップページ |
| 修練日程 | 修練日程に関する投稿 | 修練日程ページ |
| 年間行事 | 年間行事に関する投稿 | 修練日程ページ |

カテゴリーは投稿の内容を分類するためのものであり、サイト別表示制御には使用しない。

サイト別表示制御は、投稿タグを使用して行う。

6.4 投稿タグ

投稿タグは、投稿をどのサイトに表示するかを指定するために使用する。

使用するタグを以下に示す。

| タグ | 表示対象 |
| 埼玉鶴瀬道院 | 埼玉鶴瀬道院サイト |
| 志木スポーツ少年団 | 志木スポーツ少年団サイト |

タグの設定と表示対象の関係は以下のとおりとする。

| タグ設定 | 埼玉鶴瀬道院 | 志木スポーツ少年団 |
| 埼玉鶴瀬道院 | ○ | × |
| 志木スポーツ少年団 | × | ○ |
| タグなし | ○ | ○ |
| 両方設定 | ○ | ○ |

タグが設定されていない投稿は、両サイトに表示する。

両方のタグを設定した場合も、両サイトに表示する。

投稿タグはサイト別表示制御を目的として使用するため、表示対象サイト以外の用途で同じタグを利用しない。

6.5 固定ページ

固定ページは、サイトの基本的な案内情報や継続的に使用するページを管理するために使用する。

固定ページはWordPress標準の固定ページ機能を利用する。

固定ページには、サイトの構成に応じて以下のようなページを設定する。

サイト案内

修練に関する案内

年間行事に関する案内

イベント案内

イベント情報への導線

その他の固定的な案内ページ

固定ページは投稿とは異なり、原則としてカテゴリーによる分類を行わない。

固定ページの具体的な構成およびURLは、画面設計およびサイト構成に従う。

固定ページからイベント情報、イベント写真館等の関連コンテンツへリンクを設定する場合は、コンテンツ間リンクとして管理する。

6.6 イベント

イベントは、Event Organiserを利用してカレンダー形式で管理する予定情報である。

イベントは、実際の開催日や時間等を管理することを目的とする。

イベントとイベント情報は同一のデータとして扱わず、それぞれ独立したコンテンツとして管理する。

6.6.1 イベントの基本項目

イベントでは、Event Organiserが提供するイベント情報を利用して、開催日、時間、開催場所等を管理する。

主な管理項目を以下に示す。

| 項目 | 内容 |
| イベント名称 | カレンダーに表示する名称 |
| 開催日 | イベント開催日 |
| 開催時間 | 開始・終了時間 |
| 開催場所 | 開催場所 |
| イベント説明 | イベントに関する説明 |
| 繰り返し | 必要に応じた繰り返し設定 |
| 公開状態 | イベントの公開状態 |

実際の入力項目および入力方式は、利用するEvent Organiserの機能に従う。

6.6.2 サイト別イベント

イベントは、埼玉鶴瀬道院サイトおよび志木スポーツ少年団サイトで利用する。

現在は、志木スポーツ少年団サイトで埼玉鶴瀬道院サイトのイベント情報を利用する構成を基本とする。

今後、志木スポーツ少年団の活動拡大に伴い、志木スポーツ少年団独自のイベントを登録・管理できる構成とする。

イベント情報CPTとは独立しているため、カレンダー上のイベントを登録しただけではイベント情報CPTが自動生成されるものではない。

6.7 イベント情報

イベント情報は、イベントの詳細情報を管理するためのカスタム投稿タイプ（CPT）である。

イベント情報は、カレンダー機能で管理する「イベント」とは別のコンテンツとして管理する。

イベント情報では、イベントの概要、詳細説明、写真、動画等をまとめて掲載する。

6.7.1 イベント情報の基本項目

| 項目 | 内容 |
| タイトル | イベント情報の名称 |
| 本文 | イベントの詳細説明 |
| アイキャッチ画像 | イベント情報の代表画像 |
| イベント情報カテゴリー | 行事の分類 |
| 少年部 | 小学生の学年別分類 |
| タグ | 表示対象サイト・演武会等 |
| 写真・ギャラリー | イベント写真 |
| 動画 | YouTube動画 |
| 公開状態 | 下書き、公開等 |

イベント情報は、1つのイベントについて1件の情報を基本として管理する。

ただし、カレンダー上のイベントとイベント情報CPTは独立しているため、イベント情報を登録したことによってカレンダーイベントが自動生成されるものではない。

6.8 イベント情報カテゴリー

イベント情報には、行事の種別を分類するためのカテゴリーを設定する。

基本となる分類は以下のとおりである。

| 分類 | 内容 |
| 本部行事 | 少林寺拳法本部等に関する行事 |
| 大会行事 | 大会に関する行事 |
| 行事 | その他の行事 |

また、イベント情報には少年部を分類するための「少年部」を設ける。

「少年部」は、上記の行事種別とは別の分類として扱い、少年部に関する情報を小学校の学年単位で分類する。

したがって、イベント情報の分類は、行事種別と少年部の分類を独立して設定できる構成とする。

6.9 イベント情報タグ

イベント情報タグは、イベント情報の表示対象および関連する演武会等を指定するために使用する。

6.9.1 サイト指定タグ

サイト指定に使用するタグは以下のとおりとする。

| タグ | 対象 |
| 埼玉鶴瀬道院 | 埼玉鶴瀬道院サイト |
| 志木スポーツ少年団 | 志木スポーツ少年団サイト |

複数のタグを設定することができる。

タグ設定と表示対象の関係は以下のとおりとする。

| タグ設定 | 埼玉鶴瀬道院 | 志木スポーツ少年団 |
| 埼玉鶴瀬道院 | ○ | × |
| 志木スポーツ少年団 | × | ○ |
| タグなし | ○ | ○ |
| 両方設定 | ○ | ○ |

タグが設定されていない場合は、埼玉鶴瀬道院を標準の表示対象とする。

6.9.2 演武会タグ

イベント情報には、各演武会を識別するためのタグを設定することができる。

演武会タグは、イベント情報を特定の演武会に関連付けるために使用する。

サイト指定タグと演武会タグは、それぞれ異なる目的で使用する。

6.10 写真・ギャラリー

写真は、WordPressのメディアおよびNextGEN Galleryを利用して管理する。

イベント写真は、イベント単位でギャラリーを構成し、イベント情報から表示できるようにする。

6.10.1 写真管理

写真の基本的な管理単位を以下に示す。

イベント → ギャラリー → 写真

イベント情報を登録する。

対象イベントのギャラリーを作成する。

イベントの写真をギャラリーに登録する。

必要に応じて写真を編集する。

確認後、写真を公開する。

イベント情報からギャラリーを表示する。

写真は、イベント情報の本文内に直接大量に登録するのではなく、ギャラリーとしてまとめて管理する。

6.10.2 写真の公開

写真は登録した時点で無条件に一般公開するものではない。

写真提供申請によって提供された写真については、サイト管理者または管理担当者が内容を確認した上で公開処理を行う。

公開後も、必要に応じて管理者が写真の変更・削除を行う。

6.10.3 写真の削除

公開済みの写真を削除した場合、その写真はサイト上に表示されなくなる。

写真とイベント情報との間に直接的な公開状態を保持するものではないため、削除した写真について個別に「未反映」等の状態を管理しない。

6.11 動画

動画は、YouTubeを利用して管理する。

本システムでは、動画ファイルをWordPressに直接保存して管理するのではなく、YouTubeに公開された動画をイベント情報から参照する。

6.11.1 動画の登録

イベント情報の編集時に、対象イベントに関連するYouTube動画のURLを設定する。

イベント情報では、設定されたYouTube動画をページ内に表示またはリンクする。

動画自体の管理、公開状態および削除はYouTube側で行う。

6.11.2 動画とイベント情報の関係

動画はイベント情報に関連付けて表示するが、動画そのものはイベント情報CPTのデータとして保存しない。

したがって、動画の公開・非公開等の状態はYouTube側の管理状態に従う。

6.12 コンテンツ間リンク

各コンテンツは、それぞれ独立した管理単位として保持し、必要に応じてリンクによって関連付ける。

主なコンテンツ間の関係を以下に示す。

| 元コンテンツ | リンク先 | 用途 |
| 投稿 | イベント情報 | お知らせから詳細情報へ誘導 |
| 固定ページ | イベント | カレンダーへの誘導 |
| 固定ページ | イベント情報 | イベント詳細への誘導 |
| イベント情報 | 写真・ギャラリー | イベント写真の表示 |
| イベント情報 | YouTube | イベント動画の表示 |
| 埼玉鶴瀬道院 | イベント写真館 | 写真館への誘導 |
| 志木スポーツ少年団 | イベント写真館 | 写真館への誘導 |
| 少林寺拳法大会 | イベント写真館 | 写真館への誘導 |

コンテンツ間のリンクは、各コンテンツの公開状態および閲覧権限を考慮して設定する。

イベントとイベント情報をリンクする場合も、両者のデータそのものを統合するものではない。

6.13 サイト別表示制御

サイト別表示制御は、主として投稿およびイベント情報に設定されたサイト指定タグを基準として行う。

6.13.1 投稿の表示制御

投稿タグと表示対象サイトの関係は以下のとおりとする。

| タグ | 埼玉鶴瀬道院 | 志木スポーツ少年団 |
| 埼玉鶴瀬道院 | 表示 | 非表示 |
| 志木スポーツ少年団 | 非表示 | 表示 |
| タグなし | 表示 | 表示 |
| 両方 | 表示 | 表示 |

6.13.2 イベント情報の表示制御

イベント情報についても、サイト指定タグを基準として表示対象を決定する。

| タグ | 埼玉鶴瀬道院 | 志木スポーツ少年団 |
| 埼玉鶴瀬道院 | 表示 | 非表示 |
| 志木スポーツ少年団 | 非表示 | 表示 |
| タグなし | 表示 | 表示 |
| 両方 | 表示 | 表示 |

イベント情報については、タグが設定されていない場合、埼玉鶴瀬道院を標準の表示対象とする。

6.13.3 サイト間で共有するコンテンツ

サイト間で共有する必要があるコンテンツについては、対象となるサイト指定タグを設定する。

複数サイトに表示する場合は、複数のサイト指定タグを設定する。

タグ設定を行わない場合の表示仕様については、各コンテンツ種別の既定動作に従う。

6.14 コンテンツの公開状態

コンテンツには、作成・編集途中の状態と、利用者が閲覧可能な公開状態を区別する。

基本的な公開状態を以下に示す。

| 状態 | 内容 |
| 下書き | 作成・編集途中であり、一般公開しない |
| 公開 | 公開対象として表示する |
| 非公開 | 一般利用者には公開しない |
| ゴミ箱 | 削除対象として扱う |

実際に利用可能な公開状態は、WordPress標準機能、各プラグインおよびCPTの仕様に従う。

6.14.1 投稿の公開状態

投稿は、下書き状態で内容を作成・確認し、公開状態に変更することでサイト上に表示する。

公開状態であっても、サイト指定タグによって表示対象外となるサイトでは表示しない。

6.14.2 イベントの公開状態

イベントは、Event Organiserで管理される公開状態に従ってカレンダー等への表示を制御する。

6.14.3 イベント情報の公開状態

イベント情報CPTについても、公開状態とサイト指定タグを組み合わせて表示対象を決定する。

したがって、

公開状態＝公開

であっても、

サイト指定タグ＝対象サイト外

の場合は、そのサイトには表示しない。

6.14.4 写真の公開状態

写真は、登録後に管理者または管理担当者による確認を経て公開する。

写真提供申請から受け付けた写真については、確認前に一般利用者へ公開しない。

また、イベント情報自体が公開されていても、写真が公開されていない場合は、その写真を表示しない。

6.14.5 限定公開コンテンツ

イベント情報および写真には、一般公開とは別に、登録ユーザー等を対象とした限定公開コンテンツが存在する。

限定公開コンテンツについては、コンテンツの公開状態だけでなく、ユーザーの認証状態および閲覧条件を確認した上で表示する。

未認証ユーザーが限定公開コンテンツへアクセスした場合は、ログイン画面へ遷移させる。

認証後も閲覧条件を満たさない場合は、アクセス拒否として扱う。

この制御により、単にURLを直接指定しただけでは、閲覧権限を持たないユーザーが限定公開コンテンツを閲覧できない構成とする。

第7章　データ詳細設計

7.1 データ設計方針

本システムのデータは、WordPress標準機能で管理されるデータと、各プラグインおよび本システムで使用するコンテンツデータに分類して管理する。

基本的なデータ管理方針を以下に示す。

WordPress標準データを基本データとして利用する。

投稿、固定ページ、ユーザー等はWordPress標準のデータ構造を利用する。

イベントはEvent Organiserの管理データとして保持する。

イベント情報はカスタム投稿タイプ（CPT）として管理する。

イベント情報の分類にはカテゴリーおよびタグを利用する。

写真はWordPressメディアおよびNextGEN Galleryを利用して管理する。

動画データ本体はYouTube側で管理し、本システムでは参照情報を保持する。

サイト別表示制御に必要な情報は、投稿およびイベント情報のタグによって管理する。

データ間の関連付けは、各コンテンツの役割を分離した上で行う。

不要となったデータについては、WordPressおよび各プラグインの標準的な削除方式を基本とする。

本システムでは、イベントとイベント情報を別データとして扱う。

したがって、カレンダー上のイベントデータとイベント情報CPTのデータを同一レコードとして扱わず、必要に応じてリンクによって関連付ける。

7.2 WordPress標準データ

WordPress標準データは、WordPressが標準で提供するデータ管理機能によって保持する。

主なデータを以下に示す。

| データ | 主な管理対象 |
| ユーザー | ユーザーアカウント |
| 投稿 | お知らせ、修練日程、年間行事 |
| 固定ページ | 固定ページ |
| カテゴリー | 投稿の分類 |
| タグ | 投稿の表示対象等 |
| メディア | 画像等のメディア |
| コメント等 | WordPress標準機能として使用する場合 |

WordPress標準データについては、本システムが独自に同等のデータ管理機構を作成するのではなく、WordPressの標準機能を利用する。

7.3 投稿データ

投稿データは、WordPress標準の投稿機能で管理する。

投稿は以下の用途で使用する。

お知らせ

投稿カテゴリーおよびタグは、それぞれWordPress標準のタクソノミー機能によって管理する。

7.4 固定ページデータ

固定ページデータは、WordPress標準の固定ページ機能で管理する。

イベントデータは、Event Organiserによって管理される。

イベントデータは、開催日、時間、場所等の予定情報を管理するために使用する。

7.5.1 イベントデータの基本情報

本システム独自にイベント用の重複データベースを作成しない。

7.5.2 イベントとイベント情報の分離

イベント情報データは、カスタム投稿タイプ（CPT）として管理する。

イベント情報は、イベントに関する詳細情報を掲載するためのデータである。

写真そのものは、NextGEN Gallery等の写真管理機能によって管理し、イベント情報本文に写真データを直接保持することを基本としない。

7.7 カテゴリーデータ

カテゴリーは、コンテンツを分類するためのデータである。

本システムでは、投稿カテゴリーとイベント情報カテゴリーを区別して管理する。

7.7.1 投稿カテゴリー

投稿カテゴリーは以下のとおりとする。

| カテゴリー | 用途 |
| お知らせ | 道院・支部からのお知らせ |
| 修練日程 | 修練日程に関する情報 |
| 年間行事 | 年間行事に関する情報 |

7.7.2 イベント情報カテゴリー

イベント情報の行事種別は以下のとおりとする。

| カテゴリー | 用途 |
| 本部行事 | 本部等に関する行事 |

| 行事 | その他の行事 |

また、少年部については行事種別とは別の分類として、小学校の学年別に管理する。

したがって、イベント情報の分類データは、行事種別と少年部を混在させない。

7.8 タグデータ

タグは、コンテンツの表示対象サイト等を指定するために使用する。

7.8.1 投稿タグ

投稿では、以下のサイト指定タグを使用する。

| タグ | 表示対象 |
| 埼玉鶴瀬道院 | 埼玉鶴瀬道院サイト |
| 志木スポーツ少年団 | 志木スポーツ少年団サイト |

7.8.2 イベント情報タグ

イベント情報では、以下のサイト指定タグを使用する。

| タグ | 表示対象 |
| 埼玉鶴瀬道院 | 埼玉鶴瀬道院サイト |
| 志木スポーツ少年団 | 志木スポーツ少年団サイト |

イベント情報では、さらに各演武会を識別するためのタグを設定することができる。

サイト指定タグと演武会タグは目的を分けて管理する。

7.9 ユーザーデータ

ユーザーデータは、WordPress標準のユーザー管理機能によって管理する。

7.9.1 ユーザー基本情報

ユーザーの基本情報として、WordPress標準で管理される情報を利用する。

| 権限・ロール | サイト上の権限 |
| 登録日時 | アカウント登録日時 |
| 状態 | 利用可能・無効等 |

パスワードそのものを平文で保持することはせず、WordPressの認証機構に従って管理する。

7.9.2 登録申請情報

アカウント登録申請時に入力された情報については、登録処理に必要な範囲で利用する。

申請項目には以下を含む。

氏名

ふりがな（ローマ字）

メールアドレス

期生

道院（支部）名

その他支部名

メッセージ本文

登録申請の承認・差戻し等の処理は、ユーザー登録処理と関連して管理する。

実際の画像ファイルおよびメタデータの保持方法はWordPressのメディア管理機構に従う。

7.10.2 ギャラリーデータ

ギャラリーはNextGEN Galleryで管理する。

ギャラリーはイベント単位で構成し、複数の写真をまとめて管理する。

イベント情報

├── 写真3

NextGEN Gallery内部の物理テーブル構造については、利用するプラグインの仕様に従う。

本詳細設計では、プラグイン内部のデータ構造を独自に再定義しない。

7.11 写真提供申請データ

写真提供申請は、イベント写真館への写真提供を受け付けるためのデータである。

申請時には以下の情報を受け付ける。

| 項目 | 内容 |

写真提供申請を受け付けただけでは、写真を公開しない。

7.11.1 写真提供申請と写真データの関係

写真提供申請と公開済み写真は、同一データとして扱わない。

写真提供申請

│ 確認

▼

管理者・管理担当者

│ 公開処理

▼

写真・ギャラリー

申請されたURLの写真を確認し、公開する場合は、管理者または管理担当者が写真をギャラリーへ登録する。

7.12 メール通知データ

メール通知は、アカウント登録申請、承認・差戻し、写真提供申請等の処理に伴って送信する。

本システムでは、メール本文そのものをコンテンツデータとしてサイト上に公開するものではない。

7.12.1 アカウント登録関連メール

アカウント登録関連では、以下の通知を使用する。

| 通知 | 送信対象 | 用途 |
| 申請受付 | 申請者 | 登録申請を受け付けたことを通知 |
| 登録申請通知 | サイト管理者等 | 新規申請を通知 |
| 差戻し | 申請者 | 差戻し理由を通知 |
| 承認・登録完了 | 申請者 | 承認後の利用開始を通知 |

メールの送信元、宛先、件名、本文については、アカウント登録・認証に関する仕様に従う。

7.12.2 写真提供関連メール

写真提供申請時には、サイト管理者等へ申請内容をメールで通知する。

通知には、少なくとも以下の情報を含める。

提供者氏名

イベント名

提供URL

メッセージ本文

メール送信は通知処理として扱い、写真データそのものをメールデータとして保持するものではない。

7.13 サイト別データ管理

WordPress Multisiteでは、複数のサイトを1つのWordPress環境で管理する。

各サイトで利用するデータについては、サイト単位で管理されるデータと、ネットワーク全体で管理されるデータを区別する。

7.13.1 サイト構成

| サイト | 主なデータ |
| 埼玉鶴瀬道院 | 投稿、固定ページ、イベント、イベント情報等 |
| 志木スポーツ少年団 | 投稿、固定ページ、イベント、イベント情報等 |
| イベント写真館 | イベント情報、写真・ギャラリー、写真提供等 |
| 少林寺拳法大会 | 大会関連コンテンツ、SKTP管理データ |

7.13.2 サイト間データ共有

サイト間でコンテンツを共有する場合でも、必要以上にデータを重複保持しない。

埼玉鶴瀬道院と志木スポーツ少年団については、投稿タグ等によって表示対象を制御する。

イベント写真館および少林寺拳法大会との関係については、基本的にリンク・遷移によって連携する。

少林寺拳法大会のSKTPデータとイベント写真館の写真データを直接連携するデータ構造は設けない。

7.15 データ保持・削除

データの保持および削除は、データの種類に応じて管理する。

7.15.1 投稿・固定ページ

投稿および固定ページは、サイト運用上必要な期間保持する。

不要となったコンテンツは、管理者または管理担当者が内容を確認した上で削除する。

7.15.2 イベント

イベントデータは、過去のイベントについても必要に応じて参照できるよう、原則として保持する。

不要となったイベントについては、管理者または管理担当者が確認した上で削除する。

7.15.3 イベント情報

イベント情報は、過去の行事記録として利用するため、原則として保持する。

削除する場合は、関連する写真・動画等への影響を確認した上で実施する。

7.15.4 写真・ギャラリー

写真はイベント記録として利用するため、公開後も必要に応じて保持する。

削除する場合は、対象写真が表示されているギャラリーおよびイベント情報への影響を確認する。

写真を削除した場合、その写真はサイト上に表示されなくなる。

7.15.5 写真提供申請

写真提供申請は、申請内容の確認および公開処理に必要な範囲で利用する。

申請データの具体的な保存期間および削除方法については、個人情報の取り扱いおよび運用方針に従う。

7.15.7 削除時の関連データ

コンテンツを削除する場合は、関連するデータへの影響を確認する。

特に以下について確認する。

イベント情報からの動画参照

イベント写真館へのリンク

サイト別表示対象

データ削除によって他のコンテンツに不要なリンクや表示不整合が発生しないよう、管理者または管理担当者が確認した上で削除を行う。

本システムでは、イベント、イベント情報、写真、動画をそれぞれ独立したデータとして扱うため、あるデータを削除したことによって、別のデータを自動的に削除する構成を基本としない。

8.13.3 ログインできない場合

ログインに失敗した場合は、認証エラーとして処理する。

また、アカウントを持っていない利用者については、必要に応じてアカウント登録申請画面への導線を提供する。

8.14 権限外アクセス時の処理

限定公開コンテンツについては、サイト内リンクを経由せず、URLを直接指定してアクセスした場合も同じアクセス判定を行う。

したがって、リンクを非表示にするだけではなく、コンテンツへのアクセス要求そのものに対して認証・権限確認を実施する。

8.14.5 権限外アクセス時のデータ保護

権限外アクセスの場合、対象コンテンツの本文、写真、ギャラリーその他の限定公開情報を表示しない。

アクセス拒否後は、利用者に必要な範囲でログイン画面またはアクセス拒否画面を表示する。

これにより、限定公開コンテンツのURLを知っているだけでは閲覧できない構成とする。

第9章　メール・外部インターフェース詳細設計

9.1 メール設計方針

本システムでは、アカウント登録申請、承認・差戻し、写真提供申請等の処理に伴い、メールによる通知を行う。

メール通知は、利用者への案内および管理者への処理通知を目的とし、システム上の処理結果を補完するものとして使用する。

メール設計の基本方針を以下に示す。

メール送信元を統一し、受信者が本システムからのメールであることを識別できるようにする。

アカウント登録申請では、申請者および承認者に対して必要な通知を行う。

差戻し時には、差戻し理由を申請者へ通知する。

受信側メールサーバーによる拒否

第10章　エラー・例外処理詳細設計

10.1 エラー処理方針

本システムでは、利用者による入力誤り、認証状態によるアクセス制限、権限不足、コンテンツ不存在、写真・ギャラリー不存在、メール送信エラー、外部サービスエラー、プラグインエラーおよびシステムエラーを想定し、エラーの種類に応じた処理を行う。

エラー処理は、以下を基本方針とする。

利用者に対して、発生した問題を可能な範囲で分かりやすく表示する。

権限外の情報については、必要以上の情報を表示しない。

存在しないコンテンツへのアクセスは、404画面等により処理する。

認証が必要なコンテンツへの未認証アクセスは、ログインを促す。

権限不足によるアクセスは、アクセス拒否画面により処理する。

外部サービスの障害が発生した場合は、影響範囲を該当機能に限定する。

メール送信に失敗した場合でも、登録申請等の元となるデータを失わない。

システム内部の詳細なエラー情報は、一般利用者に直接表示しない。

管理者による確認が必要なエラーについては、管理者へ通知する。

エラー発生時には、可能な範囲で処理状態を維持し、二重登録や不整合の発生を防止する。

エラー処理は、WordPress、使用するテーマおよび各プラグインの標準的なエラー処理を基本とし、本システム固有の処理が必要な箇所について個別に制御する。

10.2 エラーコード体系

10.2.1 エラーコードの目的

本システムでは、発生したエラーを一意に識別し、利用者への案内、管理者による障害確認、ログ確認およびテスト時の結果確認を容易にするため、エラーコードを付与する。

エラーコードは、エラーの分類を示す英字と連番を組み合わせて構成する。

10.2.2 エラーコード形式

エラーコードは以下の形式とする。

| 項目 | 内容 |
| E | Errorを示す固定文字 |
| XX | エラー分類コード |
| NNN | 分類内の連番 |

E-IN-001

上記の場合、「入力エラー（IN）」の「001」を示す。

システムエラー

10.2.5 エラーコードの表示方針

エラーコードは、利用者向け画面では必要に応じて表示する。

利用者に表示する場合は、エラーコードと利用者向けメッセージを組み合わせる。

例：

エラーが発生しました。

しばらく時間をおいてから、もう一度お試しください。

エラーコード：E-SY-005

管理者向けのエラー情報では、エラーコードに加えて、発生日時、対象サイト、対象機能、対象コンテンツおよび取得可能なエラー情報を記録する。

エラーコードは、パスワード、認証情報、サーバー内部情報等の機密情報を含めない。

10.2.6 エラーコードの管理

エラーコードは、本詳細設計書を基準として管理する。

新たなエラー処理を追加する場合は、既存コードとの重複を避け、該当する分類コードの未使用連番を割り当てる。

既存のエラーコードは、過去のログ、テスト結果および障害記録との対応を維持するため、原則として別の意味へ変更しない。

10.3 入力エラー

入力エラーは、アカウント登録申請、写真提供申請、管理画面からのコンテンツ登録・編集等において、入力値が必要な条件を満たさない場合に発生する。

主な入力エラーを以下に示す。

| エラー区分 | エラーコード | 内容 | 処理 |

| 選択値不正 | E-IN-005 | 指定された選択肢以外の値 | 入力エラーとして処理 |
| 条件付き入力不足 | E-IN-006 | 条件に応じた必須項目が未入力 | 該当項目にエラーを表示 |

入力エラーが発生した場合は、送信処理を完了させず、入力画面へ戻して再入力を促す。

10.5 権限エラー

権限エラーは、ログイン済みの利用者が、付与されている権限の範囲を超えて機能またはコンテンツへアクセスした場合に発生する。

10.6 コンテンツ不存在

第11章　セキュリティ詳細設計

11.1 セキュリティ設計方針

本システムでは、WordPressを基盤としたWebサイトとして、利用者情報、アカウント情報、写真、イベント情報および管理機能を保護するため、認証、権限管理、入力制御、アクセス制御および管理画面保護を行う。

セキュリティ設計は、以下を基本方針とする。

WordPressの標準認証機能を利用する。

利用者ごとに必要な権限のみを付与する。

管理画面へのアクセスを適切な権限を持つユーザーに限定する。

フォームから送信される入力値を検証する。

アカウント登録申請等の公開フォームにはCAPTCHAを適用する。

メールアドレス等の個人情報を必要以上に公開しない。

限定公開写真について、未認証または権限外の利用者による閲覧を防止する。

写真提供申請を受け付ける際は、提供された情報を確認した上で公開する。

WordPress、テーマおよびプラグインを適切に更新する。

エラー発生時に、システム内部の情報を一般利用者へ公開しない。

セキュリティ対策は、WordPress本体、使用テーマ、使用プラグイン、サーバー環境および本システム固有の処理をそれぞれの責任範囲として実施する。

11.2 WordPress認証

本システムのユーザー認証は、WordPressの標準認証機能を使用する。

ユーザーはWordPressに登録されたアカウントを使用してログインし、ログイン状態に応じて各サイトおよびコンテンツへのアクセス可否を判定する。

認証に関する基本仕様は以下のとおりとする。

| 項目 | 仕様 |
| 認証基盤 | WordPress標準認証 |
| アカウント | WordPressユーザー |
| ログイン | WordPressログイン機能を使用 |
| ログアウト | WordPressログアウト機能を使用 |
| パスワード | WordPressのパスワード管理機能を使用 |
| 認証状態 | WordPressのログイン状態を利用 |
| 未ログイン | 公開コンテンツのみ閲覧可能 |
| 限定公開 | 認証状態および権限を確認 |

アカウント登録申請とWordPressユーザー登録は同一処理ではない。

アカウント登録申請を受け付けた後、管理者による確認・承認を経て、利用者がログイン可能なアカウントとして登録される。

11.3 パスワード管理

パスワードは、WordPressの標準パスワード管理機能を使用する。

本システムでは、管理者および利用者がパスワードそのものを直接管理するのではなく、WordPressが提供する認証・パスワード管理機能を利用する。

基本仕様は以下のとおりとする。

パスワードを平文で保存しない。

パスワードをメール本文へ記載しない。

パスワードを管理者が閲覧できる状態にしない。

パスワード設定・変更はWordPressの認証機能に従う。

パスワード入力値を画面上に表示しない。

パスワードをエラー情報やログに記録しない。

アカウント承認後のパスワード設定については、WordPressが提供するパスワード設定機能を使用する。

パスワードを忘れた場合は、WordPressのパスワード再設定機能を利用する。

11.4 権限管理

本システムでは、WordPressのユーザーおよび権限機構を利用して、管理機能および限定公開コンテンツへのアクセスを制御する。

本システム上のユーザー区分と権限の考え方は以下のとおりとする。

| ユーザー区分 | 基本的な権限 |
| サイト管理者 | 対象サイトの全体管理 |
| 管理担当者 | 指定されたサイトの管理・編集 |
| サイト閲覧者 | 認証が必要な限定公開コンテンツの閲覧 |
| 閲覧者 | 公開コンテンツの閲覧 |

「サイト閲覧者」は、概念上のユーザー区分であり、必ずしも独立したWordPressロールを新設することを意味しない。

権限判定では、単純なログイン状態だけでなく、対象サイト、対象コンテンツおよび公開条件を確認する。

また、管理担当者については、担当するサイトに必要な管理権限のみを付与し、担当外サイトの管理を無条件に許可しない。

11.5 フォームセキュリティ

アカウント登録申請、写真提供申請等のフォームについて、フォームから不正なデータが送信されることを防止するため、入力値の検証を行う。

主な対策は以下のとおりとする。

必須項目のチェック

入力形式のチェック

文字種のチェック

文字数・桁数のチェック

選択項目の妥当性確認

条件付き項目の入力確認

CAPTCHAによる自動送信対策

不正な入力値の処理

送信先メールアドレスの適切な管理

特に公開フォームについては、画面上の入力チェックだけでなく、送信処理側でも入力値を検証する。

フォームから受け取った値を、そのままHTML、メール本文、データベース等へ出力しないよう、使用する処理に応じた適切なエスケープまたはサニタイズを行う。

11.6 CAPTCHA

公開されているアカウント登録申請フォームにはCAPTCHAを適用する。

CAPTCHAは、人間による通常の申請と自動プログラムによる大量送信等を判別するために使用する。

CAPTCHAの認証に失敗した場合は、申請処理を完了させず、利用者へ再入力または再実行を促す。

CAPTCHAに関する認証情報や内部判定情報は、一般利用者へ表示しない。

使用するCAPTCHAの具体的なサービスおよびバージョンについては、採用するフォーム機能および運用環境の仕様に従う。

11.7 メールアドレス保護

メールアドレスは、アカウント登録申請、承認、差戻し、写真提供申請等の通知に使用する。

メールアドレスは個人情報として扱い、必要な用途以外では公開しない。

主な対策は以下のとおりとする。

一般公開ページへ利用者のメールアドレスを掲載しない。

管理画面では、必要な権限を持つ管理者のみが確認できるようにする。

メール送信時の宛先、Reply-To等を適切に設定する。

メールアドレスをエラー画面に不要に表示しない。

メールアドレスを公開コンテンツへ自動出力しない。

フォームから受信したメールアドレスを、HTMLやメールヘッダーへ不正に利用されないよう適切に処理する。

アカウント登録申請において入力されたメールアドレスは、申請者本人への通知および管理者による確認等、必要な用途に使用する。

11.8 写真への不正アクセス対策

イベント写真館では、公開写真と限定公開写真を区別し、限定公開写真について適切なアクセス制御を行う。

限定公開写真へのアクセスでは、以下を確認する。

利用者がログインしているか。

利用者のアカウントが有効か。

利用者が対象コンテンツを閲覧できる条件を満たしているか。

対象イベント情報および写真に設定されたサイトタグ等の公開条件を満たしているか。

未ログイン状態で限定公開コンテンツへアクセスした場合は、ログインを要求する。

ログイン済みであっても閲覧条件を満たさない場合は、アクセス拒否として処理する。

限定公開コンテンツは、単に画面上のリンクを隠すだけではなく、直接URLを指定したアクセスについてもアクセス条件を確認する。

写真を削除した場合は、削除された写真を引き続き表示しない。

11.9 管理画面保護

管理画面は、サイト管理者および対象サイトの管理担当者に限定して利用を許可する。

管理画面へのアクセスでは、WordPressの認証状態および権限を確認する。

権限を持たない利用者が管理画面URLを直接指定した場合も、権限チェックを行い、管理機能を利用させない。

管理画面で扱う主な情報には以下が含まれる。

投稿

イベント

イベント情報

メディア

NextGEN Gallery

ユーザー

写真提供申請

これらの管理機能について、必要な権限を持たない利用者からの操作を許可しない。

管理画面のログイン情報は一般公開しない。

11.10 不正投稿・不正写真提供対策

公開フォームからの不正な投稿や写真提供を防止するため、入力値の検証、CAPTCHAおよび管理者による確認を行う。

写真提供申請については、申請された写真を直ちに一般公開しない。

写真提供の処理は以下の流れとする。

利用者が写真提供フォームから申請する。

提供された情報およびURLを受け付ける。

管理者または管理担当者へ通知する。

管理者または管理担当者が提供内容を確認する。

公開可否を判断する。

公開する場合は、適切なイベント情報・ギャラリー等へ登録する。

公開しない場合は、公開処理を行わない。

これにより、外部から提供された写真が確認なしに公開されることを防止する。

写真提供フォームから送信されたURLやメッセージ本文についても、入力値として適切に検証・処理する。

11.11 操作・更新時のセキュリティ

管理画面から投稿、イベント、イベント情報、写真、ギャラリー、ユーザー等を登録・更新する場合は、ログイン状態および操作権限を確認する。

更新処理では、以下を基本とする。

権限確認後に処理を実行する。

入力値を検証する。

出力時に必要なエスケープを行う。

不正なパラメータによる操作を許可しない。

権限外のサイト・コンテンツを更新できないようにする。

処理途中でエラーが発生した場合は、不完全な状態を残さないようにする。

削除処理については、対象を確認した上で実行する。

WordPress本体、テーマおよびプラグインの更新については、運用環境への影響を確認した上で実施する。

更新前後に必要な確認を行い、更新によって既存機能に影響が発生した場合は、原因を確認して対応する。

11.12 セキュリティ上のエラー処理

セキュリティに関係するエラーが発生した場合は、一般利用者へシステム内部の詳細情報を表示しない。

対象となるエラーには以下を含む。

認証失敗

権限外アクセス

不正な入力

CAPTCHA認証失敗

不正なパラメータ

管理画面への不正アクセス

限定公開コンテンツへの不正アクセス

システム内部エラー

セキュリティ上のエラーについては、エラーの原因を利用者へ過度に開示することで、システム構成やアクセス条件が推測されることを避ける。

例えば、限定公開コンテンツに対して権限のない利用者が直接URLでアクセスした場合、コンテンツの内部情報やアクセス条件を表示せず、アクセス拒否画面を表示する。

また、システムエラーが発生した場合も、データベース情報、サーバー内部パス、プログラムの詳細、認証情報等を一般利用者へ表示しない。

管理者による確認が必要なセキュリティエラーについては、エラーコード、発生日時、対象サイト、対象機能等の必要な情報を管理者側で確認できるようにする。

写真提供申請の処理

写真提供申請を受け付けた場合、管理者に通知する。

管理者または管理担当者は提供内容を確認し、公開可能と判断した場合に写真をギャラリーへ登録して公開する。

提供された写真は、申請受付時点では一般公開しない。

提供写真の公開後

公開後の写真については、サイト管理者または管理担当者が必要に応じて編集・削除できる。

写真が削除された場合、提供申請データとの間に公開状態を示す直接的なリンク表示を行うものではなく、写真がサイト上に表示されなくなることで反映される。

本付録は、システムで扱う論理的なデータ項目を一覧化したものであり、具体的なWordPressテーブル、カスタムフィールド、メタキー等の実装情報は第7章「データ詳細設計」に従うものとする。

F.1.1 エラーコード形式

E-XX-NNN

E-AU-001

認証（AU）に分類される1番目のエラーを示す。

H.2 本システム固有用語の扱い

本システムでは、一般的な用語であっても、設計上の意味を明確にする必要がある場合は、本付録の定義を優先する。

特に以下の用語は、意味を混同しないようにする。

「イベント」と「イベント情報」

「イベント」はEvent Organiserで管理するカレンダー上の予定を指す。

「イベント情報」は、個々のイベントについて詳細情報を掲載するCPTを指す。

両者は同一のデータではなく、別々に管理する。

「写真」と「ギャラリー」

「写真」は個々の画像データを指す。

「ギャラリー」は複数の写真をイベント等の単位でまとめて管理・表示する単位を指す。

「サイト閲覧者」と「閲覧者」

「サイト閲覧者」は認証された利用者であり、限定公開コンテンツを含む許可された範囲を閲覧できる。

「閲覧者」は一般の未認証利用者であり、一般公開されているコンテンツを閲覧する。

「サイト管理者」と「管理担当者」

「サイト管理者」は担当サイト全体を管理する。

「管理担当者」は指定されたサイトについて日常的なコンテンツ管理・運用を行う。

管理担当者は担当サイト以外のサイトを無制限に管理するものではない。

「イベント写真館」と「SKTP」

イベント写真館は写真・ギャラリーおよびイベント情報を管理するサイトである。

SKTPは少林寺拳法大会の運営を支援する別システムである。

両者の間では直接的なデータ連携を行わず、必要に応じてリンク・画面遷移等によって連携する。

H.3 用語の変更・追加

本システムの開発・運用中に新たな用語が必要となった場合、または既存用語の定義を変更する場合は、設計書全体との整合性を確認した上で本付録を更新する。

特に画面ID、機能ID、ユーザー区分、コンテンツ種別、外部サービスおよびエラーコードに関する用語を変更する場合は、関連する設計書および対応表も併せて更新する。
